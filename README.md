# 盒盒行业研究技能包

> 一套由总入口统筹、13 个专项 Skill 协同执行的中文行业与企业研究工作流。

[![License: MIT](https://img.shields.io/badge/License-MIT-244C66.svg)](LICENSE)
[![Agent Skills](https://img.shields.io/badge/Agent%20Skills-compatible-82B29B.svg)](https://agentskills.io/)
[![Skills](https://img.shields.io/badge/Skills-14-B73F42.svg)](#包含的-skill)
[![Release](https://img.shields.io/badge/release-2026.09.21--rc7-C98B5B.svg)](release-manifest.json)

**Hehe Industry Research Skill Pack** 面向使用公开信息开展行业研究、企业研究、商业尽调和投资研究的 AI Agent。它由 `hehe-industry-researcher` 管理项目，再按任务调用市场规模、产业链、商业模式、竞争格局、财务、估值等 13 个专项 Skill。

“盒盒”是这套原创研究方法的识别前缀，因此公开版本统一使用 `hehe-*` 名称。每个专项都能独立调用；完整研究则由总入口负责开题、搜索组织、材料审核、专项验收和最终整合。

## 主要更新：交付 HTML 报告

**2026-09-21 · rc7**：完整行业研究、企业研究和行业＋企业研究，现在默认同时交付 **Markdown 主报告＋同内容 HTML 阅读版**。

- **Markdown 用于编辑，HTML 用于阅读。** 保留完整正文、数字、表格、图表和来源链接，打开浏览器即可查看。
- **统一报告版式。** 封面、侧栏目录、摘要卡、章节标题和正文表格使用随包模板；摘要引言与收尾通栏，并列结论排成卡片。
- **兼顾电脑、手机和打印。** 桌面通过目录定位章节，手机采用折叠目录和单列布局，支持离线阅读与浏览器打印／导出 PDF。

单独专项仍以各自的 Markdown 报告和必要附件为主；明确要求时可增加 HTML 阅读版。[查看报告封面和内容示例](#报告封面和内容示例)。

## 为什么做这套技能包

完整行业研究很容易出现三类问题：

- 只生成一篇大而泛的文章，没有把市场、竞争、财务和估值真正做完。
- 调用了很多模块，但每个模块只有几段摘要，无法独立复核和继续使用。
- 搜集、分析和写作混在一起，数字口径、来源冲突和推断边界难以追踪。

这套技能包把完整研究拆成清楚的工作单元，同时保留一份可直接阅读的综合报告：

```text
先确认研究问题
  → 建立范围、口径和任务卡
  → 统一检索与材料审核
  → 逐项完成适用专项
  → 检查方法、证据、计算、附件与正文完整度
  → 按研究问题整合最终 Markdown 主报告和同内容 HTML 阅读版
```

专项报告不会被综合报告替代。综合报告也不会把 13 份专项原文简单首尾拼接。

## 适合谁

- 行业研究、市场研究、战略和咨询人员。
- 企业战略、投资、并购和商业尽调团队。
- 需要分析上市公司、拟上市公司或有限披露企业的人。
- 希望把公开资料整理为可复核研究成果的内容与知识工作者。
- 需要让不同 AI Agent 按同一套研究边界协作的团队。

以下任务通常不需要启动完整技能包：

- 只查询一个简单事实或读取一个指定网页。
- 只需要一个专项，例如市场规模测算或公司估值。
- 已经有完整研究结论，只需要润色、排版或制作 PPT。
- 需要访谈、问卷、实验等一手研究设计；这些属于另一类研究工作流。

## 三种使用方式

### 1. 完整行业研究

适合回答市场多大、结构怎样、谁在竞争、行业为什么变化、主要机会和风险是什么。完整安装全部 14 个 Skill，由总入口根据课题选择适用专项。

### 2. 完整企业或行业＋企业研究

适合分析企业经营位置、财务质量、治理、估值和投资逻辑。行业＋企业完整组合会逐项检查 13 个专项，并为每项生成独立报告或明确记录不适用、降级及其影响。

### 3. 单独专项研究

可以直接调用任一专项，例如：

```text
使用 $hehe-market-sizing 测算中国商用服务机器人市场规模，
给出参数、公式、三种情景和可复核的 Excel 模型。
```

专项会自行完成必要的检索与最低材料审核，不要求先安装或调用总入口。

## 开题怎样进行

完整行业、企业或行业＋企业研究的第一次实质回复会先集中确认：

1. 研究用途和真正要支持的决策。
2. 行业、企业、业务、地域及包含和排除范围。
3. 历史期、最新信息截止日和预测期。
4. 重点问题、已有材料和允许使用的信息渠道。
5. 输出深度、必要附件及保存要求。

用户已经说明的内容只复述确认，不重复追问。只有用户明确要求“无需提问，直接开始”时，才跳过开题问题。

## 搜索、审核与证据

技能包可以使用 Agent 当前拥有的网页搜索、浏览器、数据库、MCP/API、文件解析或公开信息采集能力，不要求某个私有插件或付费服务。

总入口统一管理研究范围、关键词方向、材料索引和缺口；专项只提出本方法需要补充的事实。关键材料优先追到原文，并保留对象、时间、地域、单位、分母、样本、方法和来源关系。

如果安装了以下独立 Skill，可以协同使用，但它们不在本仓库内，也不是启动条件：

| 独立 Skill | 作用 | 仓库 |
|---|---|---|
| `sou-cha-ling`（搜查令） | 把问题设计成关键词簇、平台和带回字段 | [hexiaofeier/sou-cha-ling](https://github.com/hexiaofeier/sou-cha-ling) |
| `tanzi`（探子） | 跨平台采集公开信息并保留正文状态 | [hexiaofeier/tanzi](https://github.com/hexiaofeier/tanzi) |
| `baojie`（保洁） | 去重、分级、矛盾复核并交付证据台账 | [hexiaofeier/baojie](https://github.com/hexiaofeier/baojie) |

没有这些 Skill 时，当前 Agent 按包内后备规则完成必要的搜索和材料检查。

## 会交付什么

完整项目默认形成下面的目录：

```text
研究项目/
├── 00_开题与任务/
│   ├── 开题记录.md
│   └── 专项任务卡.md
├── 01_材料库/
│   ├── 材料索引.md
│   ├── 搜索材料/
│   └── 审核结果/
├── 02_专项分析/
│   ├── 各专项独立报告.md
│   └── 按题触发的 Excel、图源或结构数据
└── 03_最终交付/
    ├── 文本研究报告.md
    ├── 文本研究报告.html
    └── 交付清单.md
```

所有专项都必须交付 Markdown 主报告。完整行业研究、完整企业研究和行业＋企业研究还会生成同内容、可离线阅读的 HTML 阅读版；单独专项不自动增加综合 HTML。Excel、图源、结构数据和其他离线预览按照专项规则及实际计算需求触发。

最终综合报告采用摘要优先结构：只有一个一级标题，第一节是核心摘要，随后说明研究范围与口径，再按研究问题展开主体。Skill 调用情况放在交付清单中，逐行列出实际调用、降级和未调用情况。

总入口内置公开的 Markdown→HTML 生成器。安装 `Markdown` 和 `beautifulsoup4` 后，可在 `hehe-industry-researcher` 目录运行：

```bash
python scripts/build-html-report.py 主报告.md 主报告.html --report-type "行业＋企业研究报告" --scope "中国目标行业＋目标企业" --data-cutoff "YYYY-MM-DD" --version "V1.0"
```

生成器默认不覆盖已有文件，会检查正文一致性、标题结构、目录锚点和远程图片。固定使用随包模板，目录只列二级章节；保留原文编号，摘要并列结论排卡片，引言、收尾和普通段落保持通栏。正文内容和标题层级保持不变。无法运行生成器时，仍可按包内 HTML 模板手工制作并执行同样的交付检查。

## 完整报告的正文深度

字符数只用于检查完整分析有没有被压成摘要，不代替方法和证据。计数包含实质分析与表格，不包含来源清单、长篇原文、附录、验收记录和交付说明。

### 行业＋企业完整组合中的专项

| 专项 | 正文目标体量 |
|---|---:|
| 市场规模、PEST、趋势、驱动力、痛点 | 5,000—8,000 汉字 |
| 产业链 | 6,000—10,000 汉字 |
| 商业模式、竞争格局、公司画像、治理、估值、投资逻辑 | 7,000—13,000 汉字 |
| 财务分析 | 9,000—13,000 汉字 |

### 最终综合报告

| 项目类型 | 正文目标体量 |
|---|---:|
| 完整行业研究 | 25,000—40,000 汉字 |
| 完整企业研究 | 20,000—30,000 汉字 |
| 行业＋企业研究 | 40,000—60,000 汉字 |

实质分析完整且只比下限少量自然偏差时，可以记录后交付；超过下限 10% 的短缺必须补足缺失分析，或明确改为局部／有限披露报告。禁止按“还差多少字”补写、跨专项复制、同句式换变量或用方法说明凑正文。

## Excel 与其他附件

市场规模、财务分析和估值涉及实际测算时，默认生成带公式的 `.xlsx`。可以使用任何能够创建、保存并重算 Excel 的工具，不绑定特定插件。

如果当前环境无法生成工作簿，仍应交付参数、公式、计算过程和结果，并把 Excel 明确标为待生成，不能把静态表格冒充公式模型。产业链图同理：优先交付图源和可查看预览；渲染能力不可用时保留可复用图源并说明状态。

## 有限披露企业怎样处理

没有完整财报、没有连续三表或只有融资与经营数字时，Skill 不会补造财务报表。它会根据材料选择：

- 有限披露财务分析；
- 财务经营分析；
- 情景测算；
- 财务可分析性评估；
- 当前无法成立的判断与待补材料。

估值会区分当前独立经营价值、经营改善情景和条件化 IPO 情景，不把融资额、投后估值、GMV、订单或产能直接当成收入、利润和现金。

- 13 个专项全部独立交付，正文达到各自目标区间。
- 最终报告只有一个一级标题，以核心摘要起首；实质正文 39,371 个汉字，距 40,000 下限约 1.6%。

- 综合报告精确重复正文段落为 0，未使用机械补字段落。

这次回归验证的是一个具体公开信息课题。特殊行业、内部尽调资料和不同 Agent 环境仍应按实际项目复核。

## 安装

克隆仓库：

```bash
git clone https://github.com/hexiaofeier/hehe-industry-research-skill-pack.git
```

完整研究建议复制 `skills/` 下全部 14 个文件夹。安装后的结构应是 `<Skill 目录>/<Skill 名>/SKILL.md`。

| 客户端 | 常见用户级目录 | 显式调用示例 |
|---|---|---|
| Claude Code | `~/.claude/skills/` | `/hehe-industry-researcher` |
| Codex | `~/.codex/skills/` 或客户端配置的 Skills 目录 | `$hehe-industry-researcher` |
| WorkBuddy | 由应用设置的 Skills 目录 | 在 Skill 列表中选择 |

复制后新开一个会话，让客户端重新发现 Skill。只安装单个专项时，只复制对应目录即可；这种安装不能宣称具备完整 1＋13 组合能力。

## 校验

仓库校验器只使用 Python 标准库：

```bash
python scripts/validate_release.py
```

它检查 14 个 Skill 的名称与目录、总入口组合合同、包内 Markdown 链接、交付模板结构、公开包清洁度以及本地路径和私有能力泄漏。校验通过说明发布包结构完整；具体研究质量仍需用实际课题检验。

## 公开边界与维护

- 仓库不包含私有付费能力、密钥、账号、Cookie、本地维护台账或历史备份。
- 社区帖子和平台互动只支持观点、案例与信号判断，不能直接推导总体比例或经营事实。
- 动态数据、政策、价格、产品和公司状态应在使用时重新核对。
- 发现链接失效、规则冲突或行为偏差，欢迎提交 [Issue](https://github.com/hexiaofeier/hehe-industry-research-skill-pack/issues)。Issue 中请勿粘贴凭证、未公开内部材料或受版权保护的完整原文。
