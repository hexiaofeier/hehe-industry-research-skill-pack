# 行业趋势分析

本 Skill 是盒子原创行业研究 Skill 组合中负责趋势分析的专项 Skill，回答“什么变化正在发生、怎样判断它是否成立及所处状态、通过什么机制产生什么影响、接下来观察什么、什么情况会使判断降级或失效”。

## 1. 技能定位

本 Skill 只回答：什么变化正在发生；变化是否成立及所处状态；关键变量通过什么机制产生行业、市场或经营影响；后续看什么信号，什么情况会使判断降级或失效。

```text
确定任务与范围 → 整理证据与变化 → 判断趋势与状态 → 解释机制与影响 → 形成结论与跟踪条件
```

趋势不是新闻清单、热词集合、确定性预测或最终行动建议。

## 2. 分析边界

本 Skill 可以使用政策状态、竞争结构、公司经营、单位经济、用户需求、宏观传导与产业约束等现成结果，但只综合它们对“变化阶段、时间关系与未来条件”的含义，不重做这些事实本身，也不得静默覆盖原始口径或证据状态。

需要新增材料时，输出结构化补证任务：

```text
待补主张｜缺口为何会改变趋势判断｜对象/地域｜发生期与披露截止日｜所需证据形态｜建议检索方向｜可接受替代证据｜审核要求
```

搜索摘要只作线索，不能直接成为趋势事实。

### 事实与趋势的版本顺序

先建立可追溯事实快照，再综合判断变化阶段。若趋势分析提出新的经营结果、竞争变化或政策效果疑问，将其列为下一轮补证或复核任务；新资料进入新版本，不得反过来冒充本轮趋势判断的原始证据。

## 3. 启动与工作流程

- **已安装 `hehe-industry-researcher`：** 收到任务卡和材料索引后直接读取材料并执行，不重新启动路由。
- **未安装 `hehe-industry-researcher`：** 本 Skill 单独启动，在对话中确认对象、研究范围、地域、时间、用户口径要求及已有材料，再决定是否搜索。

开始执行前读取 [专项工作流程](references/专项工作流程.md)，按对应路径接任务、搜索、审核、分析、自审和交付。
交付时读取 [趋势分析交付模板](references/趋势分析交付模板.md)，按模板完成本专项成果；用户明确不落文件时，在对话中交付。

**完整交付原则。** 用户要求完整、深度或系统研究，或本专项作为 `hehe-industry-researcher` 完整研究中的适用模块时，必须先形成独立完整专项报告，不得因后续还会汇总而只返回摘要、任务卡或几条结论。只有用户明确要求局部／简版，或资料只能支持有限披露时才切换输出模式，并在报告中标明；完整度按交付模板的分析单元和参考体量检查。

## 4. 五步分析流程

以下五步构成一条完整分析链。任务规模可以不同，但不得只挑其中几步执行；某一步确实不适用时，应说明原因。

### 第一步：确定任务与研究范围

先判断本次属于哪种任务：

- **趋势扫描**：用户想知道一个行业、技术或市场正在出现哪些重要变化；先形成候选趋势，再筛选值得深入判断的项目。
- **单项趋势验证**：用户已经提出某个变化；重点判断它是否成立、发展到什么程度以及可能如何演变。

确认：

```text
趋势对象｜地域/市场｜客户或产业范围｜观察窗口｜判断时点｜推演窗口｜比较基准
```

列出包含项、排除项和边界事件。不同地区、客户群、技术路线或产业链环节可能处在不同状态，不给整个行业强行贴同一标签。

趋势扫描可从需求与用户、技术与产品、供给与成本、渠道与商业模式、竞争结构、政策与基础设施等方向发现候选变化；不机械凑满所有方向。每个进入深入分析的候选变化都保留主判断和替代解释，例如结构性需求增长、短期补库存、政策窗口或供给扩张快于真实需求。

### 第二步：整理证据并观察变化

能量化时，根据问题选择绝对量、增速、份额或结构、渗透或采用、价格或成本等观察角度，并保持对象、时间和统计口径可比；没有连续数据时，可以使用有边界的定性证据，不为量化而拼接不同口径。

建立信号登记表：

| 字段 | 含义 |
|---|---|
| 信号与时间 | 发生了什么；发生期、首次可得日与披露日分别是什么 |
| 数据版本 | 当时可得值、当前版本、修订日期与方向；无修订机制时注明 |
| 对象与覆盖 | 地区、客户群、公司或产业环节 |
| 资料来源与状态 | 材料来源、审核情况和使用限制 |
| 信号类型 | 支持/约束、供给、需求、交易、经营或结果 |
| 时间属性 | 相对目标结果属于领先、同步还是滞后信号，为什么 |
| 变化形态 | 方向、覆盖、持续、速度/加速度与分化；只填可判断项 |
| 有效窗口 | 刷新周期、适用截至时点与过期/失效条件 |
| 假设关系 | 支持、反对或无法区分哪项假设，以及可能的替代解释 |

同时分清：

1. **支持与约束条件**：政策、资本、基础设施、关键投入品、上游技术、标准和组织能力；它们解释变化为何被推动、延缓或卡住，但不能单独证明趋势兑现。
2. **供给扩张**：产品、参与者、融资、招聘、专利、扩产、渠道和内容增加。
3. **采用与需求验证**：询价、试用、招标、采购、使用频率、订单、出货和付费。
4. **交易与经营验证**：确认收入、毛利、回款、留存、续费、复购和现金。
5. **结构沉淀**：标准、专业分工、稳定客群、重复交付、退出整合和可持续经营。

社群讨论、检索热度、融资、产品发布、参展、招聘和参与者数量只能作为线索或供给信号。融资和发布不能证明需求，订单也不能自动证明利润和现金改善。

### 第三步：判断趋势是否成立及所处状态

先判断变化的方向、覆盖范围、持续时间、速度或加速度、内部差异，以及更接近 `结构性`、`周期性`、`事件驱动`、`混合` 还是 `证据不足`。

技术扩散、产品采用或商业化趋势适合进一步判断阶段；其他趋势不强制套用生命周期：

| 阶段 | 典型特征 | 必须警惕 |
|---|---|---|
| 萌芽/试验 | 机制、原型或先行用户出现，付费和重复交付有限 | 热度冒充商业化 |
| 供给扩张 | 参与者、资本、产品或产能增加，需求验证不均 | 同质供给与过剩 |
| 需求验证 | 重复购买、持续使用或明确采购出现 | 试点、补贴或单一大单外推 |
| 规模化 | 交付可复制，基础设施、组织和单位经济逐步匹配 | 规模掩盖现金和质量问题 |
| 成熟/分化 | 增速放缓，细分、品牌、效率或整合成为主要差异 | 总量放缓等同全面衰退 |
| 收缩/重构 | 需求回落、退出、产能修正或替代路线改变结构 | 周期下滑误判永久衰退 |

阶段是证据结论，不由固定渗透率或增速阈值决定。使用阶段判断时，应综合采用或渗透、需求持续性、供给行为、经营兑现和退出整合证据，并记录：

```text
当前阶段｜维持证据｜升级触发｜降级/停滞触发｜反转/分化触发｜尚缺证据｜下次复核时点
```

再检查基准、反事实和噪音：现有条件延续时会怎样；关键驱动不存在、反转或推迟时结果是否仍会发生；季节性、低基数、政策截止、单一大单、渠道压货或短期事件能否更好解释当前信号。

多个趋势并存时，判断它们是否共享驱动或证据、相互增强、存在先后依赖、相互抵消，或只在不同子市场成立。同一信号不得重复计算影响；证据不足时保留并列判断，不强行合成统一分数。

### 第四步：解释机制与影响

找出真正影响趋势走向和结果的关键变量：

```text
关键变量｜直接影响｜传导机制｜代理指标｜合理时滞｜成立条件｜替代解释｜证伪信号
```

候选变量可来自需求拐点、供给出清、产品结构、客户导入、价格、成本、产能利用、留存、库存或政策执行。最终只保留能解释主要矛盾且可以跟踪的变量。

建立机制链：

```text
触发变化 → 系统压力/客户任务变化 → 参与者响应 → 首个直接结果 → 行业或经营影响 → 竞争或产业结构后果
```

影响可表现为需求、供给、量价结构、收入、成本、毛利、现金、留存、交付周期、资本占用、责任承担或行业结构变化。机制无法连接可观察结果时，只能保留为待验证假设。涉及目标企业时，再说明该企业受到什么影响、采取了什么应对，以及相对行业和主要对手处于什么位置。

### 第五步：形成结论并设置跟踪条件

用条件化语言形成趋势判断：

```text
在[对象/地域/观察窗口]内，[变化]已经/可能发生，当前表现为[方向、状态或阶段]。
主要机制是[机制]，关键变量为[变量]，已由[关键信号]支持；
但[替代解释/缺口]仍存在。若[成立条件]持续，可能影响[行业、市场或经营结果]；
若[降级或证伪信号]出现，则应下调或撤销该判断。
```

选择能够继续跟踪的信号：

- **领先信号**：在目标结果前变化，且有明确传导理由；
- **同步信号**：与目标结果同期反映变化；
- **滞后信号**：在结果后确认趋势兑现或沉淀。

说明每个关键信号相对什么结果领先或滞后、预计时滞、刷新频率和失效条件。历史判断使用当时可得版本，当前判断说明数据修订是否改变方向、强度或阶段。

可以设置基准延续、加速、反转/重构三类触发情景，不预设概率。出现以下情况时补充资料或重做受影响的判断：

- 只有供给或传播热度，没有需求与经营验证；
- 关键时间、对象、地域或分母无法对齐；
- 相关事实存在未解决冲突；
- 关键变量没有代理指标或可观察结果。

前瞻内容不直接转成“进入、投资、退出、加码”等行动。新增信号已经不能改变方向、状态、机制、边界或证伪条件时，停止堆积材料。

持续跟踪项目使用版本差异表，不从头重写：

```text
版本/判断时点｜新增或失效信号｜被改变的方向/阶段/机制/变量｜仍未改变的判断｜变化原因｜下一复核条件
```

只有新增证据改变主要判断、关键变量、机制链、适用边界、情景或证伪条件时，才升级主结论版本；一般刷新只更新信号台账。

## 5. 验收清单

- [ ] 对象、地域、观察窗口、判断时点和推演窗口已分开；
- [ ] 关键材料已完成必要审核，未解决冲突已明确保留；
- [ ] 支持/约束侧已单列，没有冒充需求或经营兑现；
- [ ] 供给、需求、经营和结构沉淀没有互相冒充；
- [ ] 五步均已完成，确实不适用的内容已说明原因；
- [ ] 使用阶段判断时由多组证据支持，未套固定渗透率或增速阈值；
- [ ] 使用阶段判断时，升级、降级、停滞、反转或分化均有触发条件；
- [ ] 关键变量已连接主要影响、代理指标、时滞和证伪；
- [ ] 领先、同步、滞后信号说明了相对对象、发生期、可得时点、版本和有效期；
- [ ] 已检查基准、反事实、替代解释和短期噪音；
- [ ] 多趋势已检查共同驱动、增强/抵消、先后依赖和重复解释；
- [ ] 更新只改动被新证据影响的判断，并保留版本差异；
- [ ] 前瞻结论是条件性推演，没有变成最终战略行动；
- [ ] 缺证已经补充，冲突已二次检索或显式保留；
- [ ] 输出可以继续使用，且没有覆盖原始材料口径。
