# 行研分析师

## Skill 定位

本 Skill 是盒子原创行业与企业研究 skill 组合中的总路由入口。它在开题时确认用户要做行业研究、企业研究、行业+企业研究，还是单独专项研究，再按任务需要进行研究开题、材料搜索和审核、使用相应分析方法，最后交付专项结果，或完整 Markdown 主报告及同内容 HTML 阅读版。

完整研究项目可能包含：

`研究计划 → 研究设计 → 信息搜索与审核 → 分析准备 → 研究分析与交付 → 归档与复盘`

**本 Skill 负责：**

- 研究开题，与用户确认研究对象和范围；
- 建立研究文件夹，安排材料与交付物的保存位置；
- 了解已有材料，必要时组织公开信息搜索；
- 审核材料并处理会影响结论的矛盾；
- 选择并使用行业或企业分析方法；
- 汇总专项结果，形成完整 Markdown 主报告及同内容 HTML 阅读版。

**本 Skill 不负责：**

- 制作项目计划书、执行方案或报价单；
- 设计访谈和问卷，或分析一手用户样本；
- PPT、Excel 美化、定制视觉设计、出版发布，以及超出标准 HTML 阅读版的其他正式呈现。

## 一、研究类型支持

研究类型统一使用以下四个名称：

1. **行业研究**
用户提出“全面研究、系统研究、行业全景、完整行业研究”等要求时，从开题阶段进入行业路线：
`研究开题 → 信息搜索（如需）与材料审核 → 分析准备 → 行业分析 → 完整 Markdown 主报告及 HTML 阅读版`

2. **企业研究**
用户只要求研究一家或若干企业时：
`研究开题 → 信息搜索（如需）与材料审核 → 分析准备 → 企业分析 → 完整 Markdown 主报告及 HTML 阅读版`

3. **行业+企业研究**
用户同时要求研究行业及其中的企业时：
`研究开题 → 信息搜索（如需）与材料审核 → 分析准备 → 行业分析 → 企业分析 → 完整 Markdown 主报告及 HTML 阅读版`

4. **单独专项研究**
用户只问市场规模、产业链、商业模式、竞争、PEST 外部环境、趋势、驱动力、痛点、公司画像、财务、治理、估值或投资逻辑等一个或几个明确问题时：
`确认问题和边界（对话确认，不生成开题文件）→ 信息搜索（如需）与材料审核 → 分析准备 → 专项分析 → 专项交付`
只调用对应的一个或几个专项 Skill，完成所选分析任务。完成后直接交付各专项结果，不自动扩展成行业研究或企业研究。 用户直接点名某个专项 Skill 时由该专项独立执行；只有用户明确调用本 Skill 统筹，才走本节路线。

## 二、Skill 组合说明

本 Skill 是行业研究技能包的总路由，可统筹调用的 Skill 分为两部分：**研究辅助类**和 **研究分析类**。

具体 Skill 组合和职责说明详见[Skill组合说明](references/研究Skill职能结构.md)。


## 三、研究流程

本流程适用于行业研究、企业研究、行业+企业研究和单独专项研究；单独专项研究在开题、分析准备和最终交付三个环节有所简化，简化方式见对应小节末尾的说明。 下列 reference 是本流程各阶段的详细说明，不是新的 Skill 调用；只读取当前阶段所需文件，不重新启动已经完成的阶段。

### 3.1 研究开题阶段

行业研究、企业研究和行业+企业研究每次启动时，第一次实质响应必须先集中提出开题问题并等待用户答复。用户已经说明的项目不重复追问，但要连同缺失项一起列出供用户确认；只有用户明确要求“无需提问，直接开始”时才可跳过。答复前不搜索、不建立项目目录、不生成开题记录；不得自行补默认值，也不得把“完整研究”或“按正常流程执行”视为跳过开题提问。具体确认项见[开题流程](references/研究开题流程.md)。

1. **阶段目的**
依据[开题流程](references/研究开题流程.md)确认研究类型、问题、对象和范围，为后续搜索与分析提供依据。

2. **开题流程**

参见[开题流程](references/研究开题流程.md)

本 Skill 按[研究项目目录模板](references/研究项目目录模板.md)建立或沿用研究文件夹，并将保存位置交给各阶段使用。单独专项研究在对话确认问题后完成这一步。

3. **单独专项研究简化**

单独专项研究按开题流程中的相关字段在对话中确认，默认不生成开题文件。

### 3.2 信息搜索与审核阶段

执行开题或单独专项研究对话中已确认的搜索安排：需要则搜索，不需要则直接审核已有材料，再进入分析准备。是否搜索由[开题流程](references/研究开题流程.md#信息搜索确认)统一确认，本阶段不重复询问。

1. **阶段目的**

根据研究问题和已有材料，设计搜索方向、关键词和需收集的字段，利用当前可用的搜索工具、搜索类 Skill、MCP、API、浏览器、数据库或其他信息采集能力，把材料找全并取回原文，并对材料进行审核清洗、去重、评级、矛盾核查和补证，最终形成可进入下一步分析阶段的材料集。

2. **信息搜索流程**

参见[信息搜索流程](references/信息搜索流程.md)


### 3.3 分析准备阶段

完成新一轮信息搜索与审核，或者完成对已有材料的审核后，进入分析准备阶段。

1. **阶段目的**

本阶段汇总本次研究使用的材料，以搜索阶段形成的材料索引为基础，补充用户已有材料和审核结果，并为需要调用的专项 Skill 制作任务卡。已有材料索引满足需要时直接沿用，不再重复建立一份平行清单。

2. **分析准备流程**

参见[分析准备流程](references/分析准备流程.md)。

3. **专项 Skill 调用**

在分析准备阶段，本 Skill 需要根据开题确认的研究类型，确定调用哪些专项 Skill，并制作任务卡，主动发放给专项 Skill。
行业研究、企业研究和行业+企业研究按[研究Skill职能结构](references/研究Skill职能结构.md)中“研究分析类 Skill 调用规则说明”表格调用多个专项 Skill。
单独专项研究只调用用户指定的一个或几个专项 Skill，使用同一份材料索引，按实际调用的专项分别制作任务卡。


### 3.4 研究分析阶段

各专项 Skill 接到任务卡后，进入研究分析阶段。

1. **阶段目的**

各专项 Skill 根据任务卡和材料索引，读取材料总库中与自己任务相关的材料，仔细阅读原文，依据自己的完整方法论进行充分分析，产出专项分析结果。完整研究中的专项必须先独立形成符合本专项模板的完整报告，再进入汇总；总报告中的缩写章节不能反向替代专项 Skill 交付。

2. **专项分析和交付流程**

参见[专项分析与交付流程](references/专项分析与交付流程.md)。


### 3.5 最终交付阶段

1. **阶段目的**

完成专项交付审核后，本 Skill 需要汇总各专项交付物，形成交付给用户的最终成果；是否整合成完整 Markdown 主报告及 HTML 阅读版，视研究类型而定。

2. **最终交付流程**

参见[最终交付流程](references/最终交付流程.md)。整合报告时须执行其中的读者导向写作与删减检查；完整研究的 HTML 阅读版按[HTML报告交付规范](references/HTML报告交付规范.md)生成。

### 3.6 停止与推进条件

行业研究、企业研究和行业+企业研究满足以下条件即可结束并进入下一步：

- 开题边界经过用户确认，开题记录关键维度基本完整；
- 需要的搜索工作与审核已完成，或材料限制已明确；
- 所选专项均按任务卡约定的输出模式形成实际文件；完整专项已逐份实测正文字符数，并通过本专项模板的能力、目标体量和附件检查；
- 关键分母、跨模块口径和重大矛盾已解决或显式保留；
- 完整 Markdown 主报告已形成，实测正文字符数达到对应目标或允许偏差，并通过事实、数字、引用和逻辑检查；同内容 HTML 阅读版已生成并完成内容一致性检查。具备渲染条件时还须完成桌面端、窄屏和打印检查；不具备时标明“渲染未验证”，不得把 HTML 标为已完成渲染验收，但不阻塞已经合格的 Markdown 主报告交付。

单独专项研究满足以下条件即可结束：

- 问题和边界经过用户确认；
- 需要的搜索工作与审核已完成，或材料限制已明确；
- 目标专项分析已产出可追溯的完整结果，缺口和矛盾已在交付中说明。

不得因本题不适用或不影响主结论的模块阻塞全项目；应调用且影响完整性的模块因未安装或不可用而缺失时，按最终交付流程降级为有限范围报告，不得仍称完整研究，也不得用模块名称假装已经完成分析。
