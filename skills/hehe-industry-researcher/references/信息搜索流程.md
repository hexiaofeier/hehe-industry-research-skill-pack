# 信息搜索流程

沿用[开题流程](研究开题流程.md#信息搜索确认)中已确认的搜索安排；不开展新一轮搜索时，直接执行下文“材料审核”，再进入分析准备。

## 搜索方向优化

`hehe-industry-researcher` 先确定研究问题、对象边界和需带回字段；`sou-cha-ling`（搜查令 Skill）只把这些要求转成搜索主题、关键词和任务包。

如果本机安装了 `sou-cha-ling`，在搜索时调用它，并将返回结果作为本项目的统一搜索方案，不再另建一套对象池、关键词表或信源清单；按已确认的研究类型选择关键词组件：

- **行业研究**：围绕行业、细分市场、业务模式、产业链、竞争格局、PEST 外部环境、趋势、驱动力和痛点设计搜索方向。
- **企业研究**：围绕企业、业务、产品、财务、治理、估值和投资逻辑设计搜索方向。
- **行业+企业研究**：结合已确认的行业范围和企业范围设计搜索方向。
- **单独专项研究**：只使用所选一个或几个问题对应的关键词组件，并按研究对象选择行业或企业方向。

如果本机并未安装 `sou-cha-ling`，则根据开题记录和用户要求，自行设计搜索关键词和需收集的信息。注意使用多个关键词组合，并考虑中文名、英文名、简称、旧称、同义词、上下位概念和时间限定；不要只搜索一次就结束。

## 搜索能力调用

搜索能力按任务需要从当前可用能力中选择，包括 Agent 自带网页搜索与浏览、信息搜索与采集 Skill、搜索或数据 MCP/API、原始网站与专业数据库、学术论文与预印本，以及网页与文件提取能力。不限定某个工具，也不要求全部调用；按材料类型分配任务，避免同一查询无意义重复。

| 能力类型 | 包括但不限于 | 适合做什么 |
|---|---|---|
| Agent 自带网页搜索与浏览 | Web Search、WebFetch、内置浏览器、已连接浏览器 | 广泛发现网页、定位来源、打开原文和核对上下文 |
| 信息搜索与采集 Skill | 当前已安装并经过审查的公开信息采集 Skill | 跨平台搜索、批量采集、社区内容、垂直检索和正文整理 |
| 搜索或数据 MCP/API | 当前已连接且适合本题的服务 | 扩展搜索覆盖、查询结构化数据或补充垂直来源 |
| 原始网站与专业数据库 | 政府统计、监管和交易所网站、公司官网与投资者关系页面、招投标、论文、专利、行业数据库 | 获取统计数据、政策原文、公司披露、交易信息、学术和技术材料 |
| 学术论文与预印本 | arXiv 网站或 API | 研究涉及学术概念、算法、AI 模型、技术范式或前沿技术时必查；至少带回标题、作者、摘要、发布日期和原文链接，并打开关键论文核对。|
| 网页与文件提取能力 | URL 正文提取、PDF/Office 解析、OCR 等 | 已知网址或文件时，读取全文、表格、附件和扫描材料 |

**使用方法：**

1. 先用通用网页搜索或综合采集能力发现来源和线索，再打开具体页面读取原文；搜索结果摘要不能代替原文。
2. 已经知道网址、文件或数据库入口时，直接使用浏览、正文提取或文件解析能力，不必重复做广泛搜索。
3. 行业数据、公司披露、政策、论文专利和用户讨论分别使用适合它们的原站、数据库或平台能力；一个工具覆盖不全时，再换其他能力补齐。
4. 不让所有工具机械重复同一查询。只有为了覆盖不同平台、交叉发现或替代失败工具时，才重复搜索。
5. “已安装”“已配置”和“本次实际调用成功”不是一回事。调用失败时改用其他可用能力，并记录哪些渠道没有取到。
6. 复杂课题可以按行业、企业、政策、数据、技术和用户声音等方向拆分搜索任务；只使用本题需要且当前可用的能力，不要求把表中工具全部运行一遍。
7. 付费、登录、账户、隐私或外部写入遵守用户授权；能力存在不等于必须调用。

## 材料审核

审核本次分析使用的已有材料和新增材料，不因跳过搜索而跳过审核。
有 `hehe-baojie` 时调用它完成清洗、去重、评级和矛盾核查；没有时自行核对原文、主体、时间、地域、定义口径、单位分母、重复和冲突。需要补证时回到同一搜索方案追加任务，不另开一套流程；审核状态记入材料索引，重要矛盾和缺口记入审核结果。

## 搜索材料集的交付

`hehe-industry-researcher` 按[目录模板](研究项目目录模板.md)指定保存位置：搜索方案及搜索产物（含专项补搜材料）放入 `01_材料库/搜索材料/`，材料索引放在材料库本层，审核产物放入 `01_材料库/审核结果/`；已有项目使用对应位置。

**交付规则**
调用的信息搜索 Skill 有自己的工作记录时可直接复用，不重复生成。搜索结束至少保留一份可追溯的材料索引；其余记录按课题复杂度和复核需要生成，不把所有过程文件都设为默认对外交付：

| 交付内容 | 最低要求 |
|---|---|
| 公开信息搜索报告 | 多轮、多渠道或需要复查搜索覆盖时生成；记录范围、关键词、渠道、日期、主要发现、覆盖不足及有实质影响的失败或降级。简单补搜可将这些信息并入材料索引。 |
| 材料索引（搜索阶段初版） | 为每条材料记录编号、材料类型、标题、来源平台或机构、作者、发布时间、取得时间、原文链接或文件位置、正文状态和关键内容；社区材料能取得互动数据时一并记录。无权保存或转交全文时，需尽量保留摘录、标题、作者、时间和原文链接等必要信息。后续分析准备直接更新这份索引，不再另建平行清单。 |
| 关键原文或摘录 | 对进入后续分析的关键材料取得正文、表格或必要摘录，并与 Agent 摘要分开保存；明确标记“全文、摘录、仅摘要或仅元数据”，不能用搜索摘要冒充已读原文。 |
| 审核结果 | 有独立审核结果时直接引用；否则把“已核原文、仅有摘要、口径不清、存在冲突或暂不使用”等状态写入材料索引。只有重要矛盾和缺口需要另行形成审核记录。 |
| 原始记录与失败日志 | 搜索工具实际产生且对复核有用时保留位置；只记录会影响覆盖或结论的失败、限制和替代路径，不默认对外交付。 |

**交付物命名规则**
需要落地文件时，搜索交付物项目命名规范为**年月日_研究主题_交付物类型.md**，例如：

- `YYYYMMDD_研究主题_公开信息搜索报告.md`
- `YYYYMMDD_研究主题_材料索引.md`
- `YYYYMMDD_研究主题_材料原文_原文标题.md`
