# 开题流程

## 开题目的

通过已有材料和简短提问，确认本次研究的问题、对象、范围和材料情况，为后续搜索与分析提供依据。

## 开题流程

用户已经说清楚的内容直接记录，只追问影响当前研究的问题，不必按固定顺序逐项询问。

### 已有研究材料确认

询问用户已有材料及位置，优先读取用户提供的计划书、需求说明、大纲、历史报告或数据。在建立项目文件夹时，将用户提供的本地材料复制到 `01_材料库/已有材料/`，保留原件。
用户提供已有材料，不等于材料足够。
用户没提供已有材料，不等于后续没有，项目目录中仍需要给用户已有材料留有文件夹位置。

已有材料位置参考[研究项目目录模板](研究项目目录模板.md)。

### 研究类型确认

| 类型 | 在开题时确认什么 |
|---|---|
| 行业研究 | 研究哪个行业或细分赛道、关注哪些问题，不因材料中出现企业案例就自动增加企业研究。  |
| 企业研究 | 标的企业名单和标的研究重点，如研究公司整体还是某项业务或产品；可直接开展，不必先做完整行业研究。 |
| 行业+企业研究 | 分别明确行业范围和企业研究范围；企业部分可以全面研究，也可以只回答指定问题。 |
| 单独专项研究 | 针对哪个行业、企业或两者，只回答哪一个或几个问题，不自动扩大为完整研究。 |

涉及企业研究但企业尚未选定时，优先由用户指定，如果用户需要 Agent 推荐，Agent则需根据开题记录中的信息进行企业名单推荐。行业+企业研究可先做行业研究，在企业分析前明确名单。

研究类型确认仅用于指导开题时期的准备工作，可以指导搜索阶段的关键词优化和搜索方向，以及 专项 Skill 的任务卡制作的准备。但不得锁死类型，不得排除在研究过程中用户新增行业研究、企业研究、单独专项研究的需求。

需要保证用户新增任何研究需求时，`hehe-industry-researcher` 均可以补充开题记录、需要时补搜并审核、调用对应专项 Skill 并派发任务卡、专项交付审核等一系列工作流。

### 信息搜索确认

- 没有可供分析的已有材料：需要信息搜索。
- 有可供分析的已有材料：询问是否需要新一轮搜索；需要则搜索，不需要则审核已有材料后进入分析准备。用户已明确的选择不重复询问。
- 用户不需要搜索的情况，只跳过搜索，不跳过对已有材料的审核。分析中发现缺口可定向补搜；用户明确禁止搜索时，需在专项交付物中说明缺口。

### 开题记录落地

统一使用[简单开题模板](简单开题模板.md)。
先根据已有信息预填，再请用户确认尚未明确的研究类型、对象、范围和关键口径；不能把预填内容当作用户确认。不影响起步的缺项可标为待补。

行业研究、企业研究和行业+企业研究保存开题记录；单独专项研究只按相关字段在对话中确认，用户要求保存时也用同一模板。

**开题记录命名规则**：`YYYYMMDD_研究主题_开题记录.md`，保存在 `00_开题与任务/` 或已有项目的对应位置。

用户已有的明确要求照办；研究方法、专项选择和报告结构可随材料细化。改变已确认的研究对象或范围时，再与用户确认并更新记录。

### 下一步建议

简要说明：`已确认范围｜待确认或待补事项｜下一步：进入搜索或审核已有材料`。
