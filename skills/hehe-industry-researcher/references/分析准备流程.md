# 分析准备流程

## 汇总本次研究材料

目标是让所有专项 Skill 共用同一份材料总库，避免重复搜索和审核。
内容包括但不限于用户提供的已有材料、信息搜索与审核后的搜索材料集，以及对话中出现的有效材料。
材料和索引使用开题时确定的 `01_材料库/` 或已有项目的对应位置，见[目录模板](研究项目目录模板.md)。
专项补搜的新材料也汇入材料库，由 `hehe-industry-researcher` 更新同一份材料索引；保存和审核方式见[专项分析与交付流程](专项分析与交付流程.md)。

## 更新材料索引和建立专项任务卡

为每个专项 Skill 提供阅读线索和任务要求，方便专项 Skill 读取任务卡后，根据材料索引快速找到与自己任务相关的材料。字段以够用为准，只记录与“给专项交办任务”直接相关的信息；不确定或不适用时留空或写“未知”，不必为凑齐字段编造内容。

### 材料索引

执行过信息搜索时，直接沿用搜索阶段形成的材料索引，补充用户已有材料、对话中的有效材料、涉及对象、可能关联的专项、关键位置和审核状态，不再重新制作一份材料清单。没有执行新搜索时，则根据本次使用的已有材料建立索引。

材料索引落实为 Markdown 文件，命名规则为 `YYYYMMDD_研究主题_材料索引.md`。记录以下信息：

| 字段 | 填写内容 |
|---|---|
| 材料编号 | 给每份材料一个便于引用的编号，例如 M001。 |
| 标题 | 报告、新闻、政策、公告、网页或文件的实际标题。 |
| 发布时间 | 该材料对外发布或最后更新的时间；找不到时注明未知。 |
| 原文链接或文件位置 | 可以打开该材料的网址，或本地文件的实际路径。 |
| 材料类型 | 说明它是统计数据、行业报告、政策、公司披露、新闻、论文、招投标、用户讨论还是其他材料。 |
| 涉及对象 | 这份材料主要谈哪个行业、细分市场、公司、产品、地区或人群。 |
| 可能关联专项Skill | 初步判断它可能供哪些专项使用；一份材料可以对应多个专项。 |
| 关键章节/页码 | 材料较长且能定位到具体章节、页码或段落时才填；短文或网页可不填。 |
| 审核状态 | 记录 `baojie` 或最低审核的结果，例如可用、存在冲突、口径不清、待补证或暂不使用。 |

### 专项 Skill 任务卡

#### 专项 Skill 调用

`hehe-industry-researcher` 需要根据开题记录中的项目类型，在本阶段确定好调用哪些专项 Skill，制作任务卡并主动发放给专项 Skill。不能只把任务卡放在项目文件夹里等专项 Skill 自行查找。
如果用户明确由 `hehe-industry-researcher` 统筹单独专项研究，没有开题记录时直接调用用户要求的专项 Skill；同样制作任务卡并主动发放。用户直接调用某个专项 Skill 时，不经过本流程。

具体调用规则参考[研究Skill职能结构](研究Skill职能结构.md)中“研究分析类 Skill 调用规则说明”表格。

任务卡文件同时列出 13 个专项 Skill 的调用计划，字段为：`专项 Skill｜计划状态｜原因｜输出模式`。计划状态使用 `计划调用｜不适用｜用户未要求｜应调用但不可用`；共同范围和理由只写一次，不为未调用专项制作空任务卡。

#### 专项 Skill 任务卡制作

所有专项 Skill 的任务卡汇总为一份 Markdown 文件，命名规则为 `YYYYMMDD_研究主题_专项任务卡.md`，保存在 `00_开题与任务/` 或已有项目的对应位置。
共同研究边界和口径等各专项通用的内容只在文件开头写一次，不逐项重复；下方按专项 Skill 分节，只记录该专项的差异化内容。
文件开头共用研究边界与口径：

| 字段 | 填写内容 |
|---|---|
| 共同研究边界和口径 | 开题已经确认的研究类型、研究目的、研究对象、业务/产品/赛道范围、地域、时间、关键口径、单位或分母等 |

每个专项分节记录：

| 字段 | 填写内容 |
|---|---|
| 专项问题 | 本专项需要回答的具体问题，例如”2025年中国市场规模多大、按什么口径计算”。 |
| 建议阅读的材料编号 | `hehe-industry-researcher` 初步挑出的相关材料编号；只是阅读线索，不限制专项查看其他材料。 |
| 重点查找的字段 | 本专项需要从材料中取得的具体事实或数据，例如销量、价格、市场份额、政策生效日。 |
| 已知问题 | 当前已发现、可能影响本专项结论的数字、定义、时间或说法冲突，以及仍然缺少的信息；没有则写”无”，不必逐项穷举。 |
| 输出模式 | 填写 `完整专项报告｜局部专项答复｜有限披露报告`。完整行业、企业或行业+企业研究中被选中的专项默认使用“完整专项报告”；只有用户明确要求局部／简版，或关键资料确实不足时才切换，并写明原因。 |
| 预期交付 | 按本专项交付规则填写分析结果，并注明报告、模型和附件的保存目录。 |
