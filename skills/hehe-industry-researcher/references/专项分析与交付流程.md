# 专项分析与交付流程

## 专项 Skill 工作流程

`读取任务卡（共同研究边界 + 专项问题）→ 按材料索引在材料总库中定位对应材料 → 仔细阅读原文 → 依据自己的完整方法论进行充分分析 → 产出专项分析结果`

- 任务卡和材料索引只是阅读线索，专项 Skill 仍可以继续查阅材料总库中的其他材料，不受 `hehe-industry-researcher` 初步分类限制；
- 不能只根据 Skill 名称生成泛泛结论，须完成扎实、可追溯的核心分析。


### 完整专项执行门槛

完整行业、企业或行业+企业研究中，任务卡选中的专项默认逐项执行“完整专项报告”模式。每个专项先完成并保存自己的 Markdown 报告及被触发的模型或图形，再交给总路由审核；不得只返回交接摘要、若干要点或供总报告使用的一小段文字。上下文或一次对话的篇幅限制不能成为缩写专项报告的理由：没有并行能力时，按专项顺序逐个完成并落盘，再处理下一项。

只有两种情况可以改变模式：用户明确要求局部或简版；关键资料不足，只能形成有限披露报告。改变模式须在任务卡和专项报告中同时标明，不能在生成过程中静默降级。综合报告可以提炼专项结论，但必须保留并链接各自的独立交付物。

完整“行业+企业研究”的专项正文目标区间如下；其他研究类型、单线任务或有限披露模式按各专项交付模板执行。

| 专项 Skill | 正文目标区间 |
|---|---:|
| `hehe-market-sizing` | 5,000—8,000 汉字 |
| `hehe-industry-chain-map` | 6,000—10,000 汉字 |
| `hehe-business-model` | 7,000—13,000 汉字 |
| `hehe-competitive-landscape` | 7,000—13,000 汉字 |
| `hehe-pest-analysis` | 5,000—8,000 汉字 |
| `hehe-trend-analysis` | 5,000—8,000 汉字 |
| `hehe-industry-drivers` | 5,000—8,000 汉字 |
| `hehe-industry-pain-points` | 5,000—8,000 汉字 |
| `hehe-company-profile` | 7,000—13,000 汉字 |
| `hehe-financial-analysis` | 9,000—13,000 汉字 |
| `hehe-governance-capital-allocation` | 7,000—13,000 汉字 |
| `hehe-valuation-analysis` | 7,000—13,000 汉字 |
| `hehe-investment-logic` | 7,000—13,000 汉字 |

分析深度来自各专项自己的事实、计算、机制、比较和判断，不得批量套用同一段落或句式骨架后只替换变量、编号或专项名称。每个新增分析单元都要有本题独有的证据或计算、因果解释及决策含义；材料不足时先定向补搜，仍不足则按实际证据降级交付。

专项先使用任务卡和共同材料索引；只有可能改变核心结论的具体缺口才定向补搜，不重建完整对象池、关键词方案或平行材料清单。新增材料按[研究项目目录模板](研究项目目录模板.md)保存到 `01_材料库/搜索材料/`，将来源和文件位置交给 `hehe-industry-researcher` 更新同一份材料索引；有 `baojie` 则调用，否则按最低标准审核。已有项目使用对应位置。

## 专项结果核对提要

下表只列核对要点，并非强制要求的交付维度，完整交付需按各专项 Skill 自己的规定和实际情况执行。

| 调用的 Skill | 应当带回的专项结果 |
|---|---|
| `hehe-market-sizing` | 市场边界定义；测算方法与参数；用户要求时间范围的市场规模数据，可含历史数据和预测数据；至少一种情景与敏感性分析；明确标注不可外推的范围 |
| `hehe-industry-chain-map` | 产业链结构（上下游环节与参与者）；关键角色及其功能；订单流、资金流、数据流、责任流（四流）说明；主要瓶颈、权力关系与替代路径 |
| `hehe-business-model` | 行业研究看行业典型模式，企业研究看目标企业的经营模式；付款方与使用方是否分离；收入结构与成本结构；单位经济模型；现金流闭环说明 |
| `hehe-competitive-landscape` | 竞争范围界定；主要玩家与替代方案清单；市场份额或可比指标；战略群组划分；格局变化趋势 |
| `hehe-pest-analysis` | 目标行业相关的 P/E/S/T 因素；对行业的影响路径；受影响的企业类型和方向；出海课题的目标市场环境与国际关系；现实信号和不确定性 |
| `hehe-trend-analysis` | 趋势所处阶段；支撑趋势的主要信号；供需与经营层面的验证证据；判断趋势转折的条件；用于证伪该趋势的指标 |
| `hehe-industry-drivers` | 行业变化的根本原因；直接驱动因素；驱动力的传导链条；受到的约束条件；用于观察验证的具体指标 |
| `hehe-industry-pain-points` | 明确的痛点承担者（谁）；痛点发生的具体场景；造成的实际损失；现有解决方案及其缺陷；尚未解决的机会边界 |
| `hehe-company-profile` | 企业主体与业务范围界定；经营验证结果（收入、用户、产能等实际经营指标）；成长性判断；战略方向与主要风险清单 |
| `hehe-financial-analysis` | 三表关键数据与分部拆解；利润质量判断；现金流状况；资本效率指标（如 ROIC、周转率）；流动性与财务韧性评估 |
| `hehe-governance-capital-allocation` | 控制权结构；管理层激励机制；关联交易梳理；资本来源与用途；历史重大资本配置决策评估 |
| `hehe-valuation-analysis` | 估值方法与关键参数；企业价值区间测算；隐含增长或回报预期；与可比公司的对比结论；估值结论的敏感性与局限 |
| `hehe-investment-logic`（如需调用） | 投资逻辑闭环；企业或行业价值评估结论；风险与收益对比分析 |

## 专项交付

各专项按自己的交付及命名规则，将底稿、报告、模型和附件平铺保存到任务卡指定的 `02_专项分析/`，不再分行业、企业或专项子目录；已有项目使用对应位置，由 `hehe-industry-researcher` 检查实际交付。

- 行业研究默认包含以下 8 个专项 Skill 的交付物：`hehe-market-sizing`、`hehe-industry-chain-map`、`hehe-business-model`、`hehe-competitive-landscape`、`hehe-pest-analysis`、`hehe-trend-analysis`、`hehe-industry-drivers` 和 `hehe-industry-pain-points`。研究目的包含行业投资机会、风险收益或退出条件时，另外调用 `hehe-investment-logic`；不包含投资问题时不调用。
- 企业研究默认包含以下 5 个专项 Skill 的交付物：`hehe-business-model`、`hehe-competitive-landscape`、`hehe-company-profile`、`hehe-financial-analysis`、`hehe-governance-capital-allocation`。实际调用了哪些专项，就汇总哪些专项的交付物。
- 单独专项研究按所选各专项 Skill 的交付规则直接交付分析结果。

## 专项交付审核

`hehe-industry-researcher` 需要对各专项 Skill 的分析结果进行信息审核，确保结论可追溯、逻辑自洽、数据和事实准确。

完整组合研究使用同一张验收矩阵记录全部 13 个专项，至少包括：`专项 Skill｜计划状态｜实际状态｜输出模式｜实际报告文件｜核心能力是否齐全｜主要证据或计算是否展开｜触发附件是否完成｜正文字符数／目标区间｜未调用、降级或退回原因｜对完整性的影响`。实际状态使用 `已完成｜有限完成｜未调用·不适用｜未调用·用户未要求｜应调用但不可用`。进入最终综合前，必须逐份实际统计正文字符数并填入矩阵；低于目标下限时先补足缺少的分析单元、证据和推理，实质分析完整且差距不超过下限 10% 时可记录偏差后通过，超过 10% 则退回。达到字数但缺方法、证据或解释仍不通过。只为补体量新增的“深化复核、验收补充、字数说明、交付记录、通用边界或更新流程”不计入正文并应删除；来源清单、附录、跨专项复制、同义重复、近似模板改词或零散补句同样不计入。不得在写作过程中按“还差多少字”追加内容；所有适用专项通过前，不进入最终综合。
有`baojie`时，用其检查事实、数据、引用、证据强度与矛盾；无`baojie`时至少核对信息搜索的原文、主体、时间、地域、定义口径、单位分母、重复和冲突。

`hehe-industry-researcher` 按问题安排处理：

- **事实或来源问题**：内容错误、相互矛盾、证据不足或来源不可靠时，组织定向搜索、补证和二次审核，标明证据状态。
- **口径或计算问题**：核对对象、时间、地域、定义、单位和分母，由受影响的专项修正数据、取值、公式或模型并重算。
- **解释分歧**：由受影响的专项比较主解释和最强替代解释，必要时补证，再修正判断。
- **案例与总体不一致**：先查是否可比，再判断是个例、分群差异，还是总体结论需要修正；无法确定时保留分歧，不把可见案例直接外推总体。

修正后，`hehe-industry-researcher` 复查受影响的专项结果；专项审核及跨模块矛盾处理记录放在 `01_材料库/审核结果/`，已有记录直接更新。
