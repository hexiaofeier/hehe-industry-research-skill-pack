# 最终交付流程

## 最终汇总与成文

完成专项交付审核后，所有最终版专项交付物需交由 `hehe-industry-researcher` 进行汇总、编辑和成文，并形成交付用户的最终 Markdown 主报告。完整行业研究、完整企业研究和行业+企业研究还须生成同内容 HTML 阅读版。两种文件连同附件按[研究项目目录模板](研究项目目录模板.md)保存到 `03_最终交付/` 或已有项目的对应位置。汇总可以去重和提炼，但不得删除、覆盖或以总报告短章节替代已经验收的独立专项报告。

提纲、写作底表、草稿和交付质检单如需落文件，放在 `03_最终交付/过程稿/`；通过检查的报告定稿放在 `03_最终交付/` 本层。报告命名按 `hehe-research-text-report` 的规则，无该 Skill 时用 `YYYYMMDD_研究主题_文本研究报告.md`；用户或项目规范优先。

如果本机安装了 `hehe-research-text-report`，则 `hehe-industry-researcher` 按照该文本报告写作规则，将上述材料整合为一份完整、连贯、通畅、可读性强、可编辑的 Markdown 报告。如果没有安装 `hehe-research-text-report`，则由 `hehe-industry-researcher` 自行整合为完整 Markdown 报告，要求至少报告结构清晰、核心结论站得住脚、证据准确丰富、论证逻辑经得住推敲，没有明显逻辑漏洞和前后矛盾。

**读者导向的写作与删减**

- 正文围绕结论、证据、推理及其含义展开。删掉后不影响读者理解和判断的解释，直接删除。
- 会改变结论的口径、假设、条件和风险融入相应判断；同一事项集中说明一次，保留原有判断强度。
- 内部审核、资料取舍和研究执行过程留在底稿；正文只呈现其对结论的实质影响。
- 摘要、标题、正文、表格、图注及图内脚注统一执行；任何篇幅下均适用，不为字数目标补回无效解释。

报告成稿后，如果本机安装了 `hehe-research-delivery-qc`，调用它完成交付前质检；没有安装时，由 `hehe-industry-researcher` 至少检查事实与引用是否对应、数字与口径是否一致、正文是否存在逻辑矛盾，以及已知限制是否如实说明。发现问题时，只返回受影响的分析或审核环节处理，修正后再次检查。

## HTML 阅读版

完整行业研究、完整企业研究和行业+企业研究默认在 Markdown 定稿后生成同名 HTML 阅读版。Markdown 是可编辑主稿和内容基准；HTML 只重组版式与阅读组件，不改变事实、数字、引用、口径、证据等级或结论强度。单独专项研究不自动增加 HTML，除非用户或任务卡明确要求。

HTML 按[HTML报告交付规范](HTML报告交付规范.md)制作，优先使用公开随包提供的 `../scripts/build-html-report.py`，无法运行脚本时再使用[研究报告 HTML 模板](../assets/研究报告HTML模板.html)手工制作。页面应可离线打开，不依赖外部字体、样式库或脚本；远程图像需嵌入文件或转换为稳定的项目内相对路径。正文不得展示 Skill 调用过程、内部审核记录或写作过程，这些内容仍放在交付清单和项目底稿中。

生成后逐节核对 Markdown 与 HTML：所有实质章节、核心结论、数字、表格、图表、来源和附件入口均应保留，允许调整版式和信息层级，不得把完整正文压缩成摘要页。具备渲染条件时，至少完成一次桌面端、一次窄屏和一次打印预览检查，并核对目录锚点、图像加载、表格横向滚动和来源链接。当前环境无法实际渲染时，仍须生成 HTML，并完成标题层级、锚点、项目内资源、来源链接和内容映射的静态检查；在交付清单标明“渲染未验证”，不得把 HTML 标为已完成渲染验收，但不阻塞已经合格的 Markdown 主报告和其他附件交付。

## 交付内容清单

默认对外交付包括：

1. 一份整合后的可编辑 Markdown 主报告；
2. 一份与 Markdown 内容一致、可离线阅读的 HTML 阅读版；
3. 各专项实际触发的 Excel、图源、结构数据表或其他必要附件；
4. 一份与实际文件一致的交付清单，包含本次 Skill 调用情况。

开题记录、材料索引、专项任务卡、各专项完整底稿、证据台账、审核记录、矛盾处理表和写作过程稿保存在项目目录中，供复核和续作使用；只有用户要求，或它们对理解结论确有必要时才随最终成果交付。主报告只保留会改变结论的口径、限制和待补证事项。

完整报告按平行章节展开：`核心摘要 → 研究范围与口径 → 按研究问题组织的报告主体 → 其他说明、附录与待补证内容（按需）`。核心摘要必须是首个正文章节，直接给出主要结论、关键证据及其决策含义。

总报告只能有一个一级标题。独立专项报告留在 `02_专项分析/` 并由调用表或交付清单链接；总报告正文不得再出现“某某专项报告”标题，不得把各专项原文依次改级拼接。正文按研究问题综合事实、计算和跨专项判断，同一证据只在最能推进结论的位置展开。

Skill 调用情况表放在交付清单中。字段为：`类别｜Skill｜状态｜本次职责或产物｜未调用或降级原因｜对完整性的影响`。主 Skill、实际调用的辅助 Skill和 13 个专项 Skill 均一行对应一个 Skill，13 个专项不得合并成一行；不罗列与本题无关的工具。状态与专项验收矩阵一致，公开版使用实际加载的 `hehe-*` 名称。

完整综合报告的正文目标体量为：完整行业研究 25,000—40,000 汉字；完整企业研究 20,000—30,000 汉字；行业+企业研究 40,000—60,000 汉字。交付前实际统计正文字符数并写入交付检查；低于目标下限时先补足缺失的分析、证据和推理，实质分析完整且差距不超过下限 10% 时可记录偏差后交付，超过 10% 则不能称完整报告。正文中的实质分析和表格计入，来源清单、原文摘录、附录长表、验收记录、字数说明、交付状态和通用更新流程不计入。报告不得设置只为补体量的“深化复核、验收补充、字数补充、结尾复核”等章节，不得机械拼接专项全文、复用通用段落、批量套用同一句式后只替换变量，或追加零散补句；此类内容应删除后重新计数。不得在写作过程中按“还差多少字”追加内容；高于上限时检查重复，不以字数替代核心能力、证据和论证。

本题适用且影响完整性的专项均已完成时，可称完整行业研究或完整企业研究。应调用的专项因未安装或不可用而缺失时，标题和摘要标明“有限范围”，列出未评估部分及其对结论的影响；因本题不适用而不调用的专项不算缺口。

按研究问题和实际完成的分析组织章节；未完成的部分说明缺口，不为凑章节补写结论。

行业研究内容可参考：
`核心摘要｜研究范围与口径｜市场规模与预测｜产业链结构｜主要商业模式｜市场竞争格局｜宏观与政策传导｜趋势阶段｜发展驱动力｜行业痛点｜投资逻辑与机会（如适用）｜其他说明、附录与待补证内容（按需）`

企业研究内容可参考：
`核心摘要｜研究范围与口径｜主体与披露边界｜业务和经营验证｜市场/产业位置｜商业模式｜竞争位置｜增长与财务质量｜治理和资本配置｜外部暴露与趋势｜风险与反例｜估值/投资（如适用）｜其他说明、附录与待补证内容（按需）`

## 单独专项研究简化

单独专项研究按所选各专项 Skill 自己的交付规则交付结果，不另行生成完整行业或企业报告。分析中发现的缺口或矛盾会实质影响结论时，需在交付中明确标注，不得隐去不表。
