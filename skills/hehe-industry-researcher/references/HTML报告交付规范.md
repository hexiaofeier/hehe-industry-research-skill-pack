# HTML 报告交付规范

本规范用于 `hehe-industry-researcher` 的完整行业研究、完整企业研究和行业+企业研究。HTML 是 Markdown 主报告的阅读版，目标是让读者快速找到结论、证据、图表和来源。

## 一、输入与边界

- 输入为已经通过内容质检的 Markdown 主报告及其图表、数据和附件。
- Markdown 是内容基准。HTML 可以调整信息层级和版式，但须保留全部实质章节、核心结论、数字、表格、图表、来源和附件入口，不得把完整正文压缩成摘要页，也不得改写口径、证据等级或结论强度。
- 单独专项研究不默认生成 HTML；用户或任务卡明确要求时可使用本规范。
- 页面不展示 Skill 调用过程、内部审核记录、写作说明和其他只服务于生产过程的内容。

## 二、视觉系统

采用深蓝侧栏、浅灰蓝画布、白色正文页和少量状态色。颜色按语义使用：

| 变量 | 色值 | 用途 |
|---|---:|---|
| `--canvas` | `#EEF3F7` | 页面背景 |
| `--paper` | `#FFFFFF` | 报告正文与卡片 |
| `--ink` | `#17212B` | 正文与主标题 |
| `--muted` | `#667482` | 元信息、图注、次要说明 |
| `--line` | `#DCE4EA` | 分隔线、表格边框 |
| `--blue` | `#245B78` | 结构、目录、主要数据 |
| `--blue-deep` | `#173F58` | 侧栏、封面深色区 |
| `--blue-soft` | `#DCEAF3` | 蓝色提示底 |
| `--red` | `#A9474A` | 关键结论、主要风险 |
| `--amber` | `#B8822D` | 条件、观察项 |
| `--green` | `#4F806B` | 正向结果、已验证项 |

蓝色承担结构和主要信息。红、琥珀、绿只标记有明确语义的结论，不给普通段落批量着色。关键判断不能只靠颜色表达，还要有文字标签或标题。

字体优先使用系统中文字体：`Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。正文行高 1.75 左右，单行建议不超过 42 个汉字。

## 三、页面结构

桌面端采用固定深蓝目录栏和居中的白色正文页：

- 目录栏宽约 286px，展示报告名、章节目录、当前阅读位置和打印入口。
- 二、三级标题合计不超过 40 个时，目录展示二级和三级标题；超过 40 个时只展示二级标题，避免长报告目录淹没正文结构。正文标题不因目录精简而删除。
- 正文页最大宽度约 1060px，章节之间保留明显留白。
- 宽度小于 1080px 时隐藏固定侧栏，改用正文顶部的可折叠目录。
- 宽度小于 720px 时正文铺满屏幕，表格允许横向滚动，卡片改为单列。

正文按以下顺序组织：

1. 封面：报告标题、结论型副标题、日期、口径和版本。
2. 核心摘要：4—8 条结论卡，每条只表达一个判断。
3. 报告主体：按研究问题编排二级章节，标题同时给出维度和结论。
4. 数据与图表：重要数字使用指标卡，比较关系优先用图，其次用表。
5. 来源与附件：来源链接、图表口径、相关附件入口。

## 四、组件规则

- **章节标题：** 二级标题使用蓝色结构线和编号；标题直接给出本节结论。
- **摘要卡：** 适合并列结论，不把长段落拆成大量卡片。
- **指标卡：** 同时显示数值、口径/时间和一句含义；不展示没有口径的孤立数字。
- **结论提示：** `.read.red` 表示主要风险或否定判断，`.read.amber` 表示条件和观察项，`.read.green` 表示已验证的正向结果。
- **表格：** 表头使用深蓝底色；数字右对齐；窄屏允许横向滚动，不缩小到无法阅读。
- **图表：** 优先使用内嵌 SVG；图内必须有标题、单位、图例和来源。图片使用明确的 `alt` 文本。
- **脚注与来源：** 放在对应图表或段落附近；长来源列表集中在文末。

## 五、离线、可访问与打印

- CSS 和必要脚本写入 HTML 文件，不依赖 CDN、在线字体或远程脚本。
- 图像使用 data URI 或项目内稳定相对路径。使用相对路径时，相关文件必须随报告交付。
- 使用 `header`、`nav`、`main`、`section`、`figure`、`footer` 等语义标签；全页只有一个 `h1`，标题层级连续。
- 目录链接可用键盘访问；当前章节状态由脚本增强，脚本失效时目录仍可使用。
- 打印样式隐藏目录、按钮和屏幕专用元素，采用 A4 页边距，避免标题、卡片和图表在分页处被截断。

## 六、生成步骤

1. 确认 Markdown 主报告已定稿，图表和来源链接可用。
2. 优先使用随总入口公开提供的 `scripts/build-html-report.py` 生成阅读版。脚本只依赖公开 Python 包 `Markdown` 和 `beautifulsoup4`；缺少时运行 `python -m pip install Markdown beautifulsoup4`。
3. 运行示例：

   ```bash
   python scripts/build-html-report.py 主报告.md 主报告.html --report-type "行业＋企业研究报告" --scope "中国目标行业＋目标企业" --data-cutoff "YYYY-MM-DD" --version "V1.0"
   ```

   脚本默认不覆盖已有 HTML；确需覆盖时显式增加 `--overwrite`。它会处理旧式管道表格空行，将核心摘要转换为阅读卡片，并检查一级标题、摘要顺序、正文文字一致性、重复锚点、失效内部链接和远程图片。
4. 无法运行脚本时，复制[研究报告 HTML 模板](../assets/研究报告HTML模板.html)到项目 `03_最终交付/`，根据任务替换报告类型、封面、摘要、全部实质章节、图表、来源和附件入口，并删除未使用的示例组件。模板中的主体章节只示范组件和版式，实际目录必须来自 Markdown 主报告。
5. 保持 Markdown 与 HTML 文件名主体一致，扩展名分别为 `.md` 和 `.html`；项目命名规范优先。
6. 逐节核对 Markdown 与 HTML 的章节、结论、数字、表格、图表、来源和附件入口。具备渲染条件时，在桌面端和窄屏各渲染一次，再执行打印预览；无法渲染时执行静态检查，并在交付清单标明“渲染未验证”。

## 七、交付检查

- [ ] 标题、日期、版本和研究口径与 Markdown 一致。
- [ ] Markdown 的全部实质章节、核心结论、数字、表格、图表、来源和附件入口均已映射到 HTML，没有遗漏、擅自新增或弱化结论。
- [ ] 目录锚点全部可达，当前章节提示正常。
- [ ] 图像、SVG、表格和来源链接可用。
- [ ] 具备渲染条件时，1440px 桌面端无内容遮挡，390px 窄屏无正文横向溢出；无法渲染时已标明“渲染未验证”。
- [ ] 表格可横向滚动，文字不被压缩到不可读。
- [ ] 关闭网络后仍能正常打开和阅读。
- [ ] 打印预览不显示侧栏和按钮，关键组件没有被截断。
