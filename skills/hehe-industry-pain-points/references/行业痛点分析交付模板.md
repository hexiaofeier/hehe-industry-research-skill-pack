# 行业痛点分析交付模板

## 一、交付载体

除非用户明确要求不落文件，否则必须生成可编辑 Markdown 主报告。用户明确不落文件时，在对话中按第二节结构完整交付。

Excel、CSV 或关系图只在第三节所列条件触发时生成；没有计数、复核、数据交换或复杂角色路径展示需要时，不另做附件。

## 二、Markdown 主报告

### 完整度与展开要求

先确定输出模式：

- **完整专项报告：** 用户要求完整、深度或系统研究，或者本专项被纳入 `hehe-industry-researcher` 的完整研究时使用。必须覆盖本模板列出的适用主体章节。
- **局部专项答复：** 只在用户明确询问一个局部问题或明确要求简版时使用，只展开与该问题直接相关的章节。
- **有限披露报告：** 只在关键资料确实不足时使用；仍需充分分析现有证据能够支持的内容，不能只交缺口清单。

完整报告的核心主体章节不能只有标题、事实清单、新闻罗列或一张没有解释的表。每项主要结论至少完成“结论 → 关键证据或计算 → 机制、比较或变化原因 → 对本题的含义 → 成立条件或翻转点”的闭环；表格之后解释最重要的差异和意义。

**完整模式正文目标体量：** 完整行业痛点分析一般为 5,000—8,000 汉字。 这是完整度检查线，不是写作配额；交付前必须实际统计正文字符数并记录结果。统计只包括推进本题结论的分析；来源清单、原文摘录、附录长表、方法或交付说明、验收记录、通用边界和更新流程不计入，也不得跨专项复制或批量套用同一句式后只替换变量。低于下限时先逐项复查并补足被压缩的核心能力；实质分析已经完整且差距不超过下限 10% 时，可记录偏差后交付，不得为贴线补字。差距超过 10% 且不属于局部或有限披露模式时，不得作为完整专项报告交付。超过上限也不代表更好，应删除重复结论、同义改写和只为防止质疑的说明。


完整任务按以下顺序展开：

1. **核心摘要**：一句话回答哪些问题构成当前核心痛点，再列承担者、现实损失、现有替代、当前重要性和主要边界。
2. **研究范围与判断标准**：行业或细分市场、地域、观察期、重点参与者与任务，以及本轮如何识别痛点。
3. **痛点总览**：用简表列出承担者、场景或节点、现实损失、现有替代、当前判断和重要程度。
4. **核心痛点与现实损失链**：说明表面症状、形成原因、承担者、实际后果、应对行为和持续或缓解机制。
5. **替代方案、适用分群与反例**：说明现有办法解决了什么、还缺什么、负担是否转移，以及哪些对象、时期或条件下结论不成立。
6. **综合结论与后续观察**：给出 `成立｜条件成立｜不成立｜暂不判断`，说明不可外推范围及会削弱或撤销判断的条件，不重复摘要。
7. **其他说明、附录与待补证内容（按需）**：放候选台账、计数与分母、证据映射、来源、材料边界和补证任务。

章节名称和篇幅可按课题调整，但不要把过程台账代替结论，也不要把痛点判断直接写成产品方案、市场规模或投资建议。

## 三、其他交付物

| 触发条件 | 交付物 | 最低内容 |
|---|---|---|
| 候选材料需要去重、计数、分母核对、跨角色复核或持续更新 | `.xlsx` | 范围与单位、承担者—任务—节点、候选、损失链、证据形态、替代、分群、计数与分母、反例、结论和补证 |
| 只需交换一张已整理的候选、证据或结论长表，且没有公式 | `.csv` | 痛点 ID、分析单位、来源、损失类型、替代、反例、适用范围和判断状态 |
| 多角色、任务或节点关系仅用表格难以辨认 | 报告内 Mermaid 图；用户要求独立图时再另存图源和展示图 | 承担者、任务、节点、负担转移方向和 ID 与工作表一致 |
| 样本较少且无需计数，主报告能够完整呈现 | 不生成附件 | Markdown 保留候选依据、损失链、替代和反例 |

附件字段以[行业痛点分析工作表](行业痛点分析工作表.md)为准，按任务裁剪，不交付未填写的空工作簿。出现次数不得自动转换成行业发生率或优先级。PPT 和视觉排版只在用户明确要求时制作。
同一数据表需要公式时使用 Excel；只交换无公式长表时使用 CSV，不同时生成两份重复附件。

## 四、保存与命名

- 保存位置按[专项工作流程](专项工作流程.md)：有路由时使用任务卡指定位置；单独启动时默认保存到当前任务工作文件夹；用户指定位置时按其要求保存。
- 主报告：`YYYYMMDD_研究主题_行业痛点分析.md`。
- 附件：`YYYYMMDD_研究主题_行业痛点分析_附件名称.扩展名`，附件名称写具体用途，如`候选台账`、`计数与分母表`、`证据映射表`。
- 研究主题写清行业或细分对象，企业研究加企业名；版本号按需添加。用户或项目另有命名规范时优先遵守。

## 五、信息缺口

只对会改变痛点是否成立、承担者、现实损失、适用范围或重要程度的缺口建立补证任务：

`痛点候选｜待补字段｜对象/角色/情境｜地域/期间｜所需的原文或现实损失/结果｜用于区分的解释｜可接受替代｜补充后更新哪一部分`

未解决缺口只限制相应候选或外推范围，其余能够确认的损失链、替代和反例继续完成。

## 六、交付条件与交付前检查

当核心候选的承担者、损失链、替代、持续或关键时点机制、反例和结论边界已经清楚，新增材料不太可能改变核心判断时，即可交付。

出现以下情况时，暂停判断、补充资料或降低结论强度：

- 承担者、任务、节点、情境或时期无法对齐；
- 只有供应商话术、单一抱怨或抽象挑战，没有现实损失；
- 原始材料尚未整理到能辨认承担者、任务和损失；
- 经营损失、节点受阻或驱动原因缺少事实依据，且会改变痛点判断；
- 计数单位、分母、重复关系或材料形成过程说不清；
- 关键事实或版本矛盾尚未处理。

交付前检查：

- 核心摘要先给痛点结论，研究范围和判断标准单独成节；
- 抱怨、需求、风险、产业瓶颈影响和供应商卖点没有直接写成现实痛点；
- 每项核心痛点都能连到承担者、任务或节点、现实损失、现有替代及未解决机制；
- 共性、分群、时期、材料偏差和反例已经处理，有限计数带单位、去重和分母；
- 优先级有现实损失和适用范围依据，没有由出现次数直接推出；
- 报告与附件的 ID、口径、计数、状态和结论一致，文件可打开。
