# PEST 外部环境分析工作流程

本文件与同目录的 `SKILL.md` 配套，说明本专项从启动到交付的两条路径。分析方法和验收以主 Skill 及本题所需的 P/E/S/T reference 为准。

## 1. 选择启动路径

- **由 `hehe-industry-researcher` 调用：** 收到任务卡和材料索引后直接执行，不重新启动路由或开题。
- **用户直接调用本 Skill：** 本 Skill 独立确认问题和范围并执行，不把 `hehe-industry-researcher` 或其他 Skill 作为启动条件。

## 2. 接任务或确认范围

- **由路由调用：** 读取任务卡中的研究范围、专项问题、已有材料、待补信息和预期交付，再按材料索引读取原文。仍有会改变结果的歧义时，交回路由补充确认。
- **单独启动：** 读取用户描述和已有材料，在对话中确认对象、业务范围、地域、时间、研究目的和用户已有口径。用户已说明的内容不重复询问，不要求另做开题文件。

确认本次是完整 PEST、一个维度还是几个维度。PEST 始终分析行业外部环境；如果任务来自企业研究，用目标企业的相关业务确定行业和地域范围，交付该行业的 PEST 分析，不另设企业版。

涉及出海时，以目标国家或地区为主要地域，同时确认母国、目标市场以及需要关注的跨境关系。

## 3. 信息搜索

### 组合模式

读取其 `references/信息搜索流程.md` 并按任务卡执行。已有材料足够时直接分析；发现关键缺口时定向补搜。

### 独立模式

先看已有材料；没有材料就搜索，有材料时确认是否需要补搜。用户明确不联网时，只分析现有材料并说明限制。

1. **设计关键词。** 有 `sou-cha-ling`（搜查令 Skill）时调用 PEST 对应关键词组件；没有则按对象、地域、时间和 P/E/S/T 所需信息组合关键词。
2. **选择能力。** 检查当前实际可用能力，不要求全部使用。

| 能力 | 示例 | 用法 |
|---|---|---|
| 网页搜索与浏览 | Web Search、WebFetch、内置或已连接浏览器 | 发现来源并打开原文 |
| 信息采集 Skill | `tanzi`、`last30days`、`agent-reach` 等 | 跨平台、批量、社区或垂直采集 |
| 搜索与数据 MCP/API | Exa、Tavily、Serper 或其他已连接服务 | 扩展检索和结构化数据 |
| 原始网站与专业数据库 | 政府统计、监管/交易所、公司官网、标准、招投标、行业数据库 | 获取统计、政策、披露、标准与执行记录 |
| 学术论文与预印本 | arXiv 网站或 API | 涉及学术概念、算法、AI 模型或前沿技术时必查并核读关键论文 |
| 网页与文件提取 | URL 正文提取、PDF/Office 解析、OCR | 读取已知网页、文件、表格和附件 |

3. **取得原文。** P 优先政府、立法、监管、海关、贸易与国际组织原文；E/S 优先统计和调查原表、方法说明；T 优先论文、标准、专利、产品和部署材料。搜索摘要只作线索。
4. **补齐缺口。** 一个渠道不足或失败时换其他能力，保留标题、来源、日期、链接或文件位置、关键摘录和未取得内容。

### 材料审核

有 `baojie`（保洁 Skill）时调用；不可用时至少核对原文、主体、时间、地域、适用对象、定义、单位、分母、版本、重复和冲突。政策目标、经济指标、社会讨论和技术进展不能直接代替已经发生的行业影响；证据不足时降低结论强度。

## 4. 分析与自审

按主 Skill 的共用方法及本题所需 reference 分析，不要求先调用其他专项 Skill。完整 PEST 检查四维，单一或组合任务只做所选维度。

发现关键缺口时先补证；暂时无法解决时，只降低或暂停受影响的判断，其余可确认部分继续。提交前检查范围、来源、时间、口径、版本、现实信号、矛盾、反例、限制和不可外推范围。

## 5. 交付与返修

按[PEST 外部环境分析交付模板](PEST外部环境分析交付模板.md)交付。

- **由路由调用：** 保存到任务卡指定位置，交回实际文件清单、新增材料和未解决问题；路由退回时修正受影响部分并重新自审。
- **单独启动：** 自审后直接交付，默认保存到当前任务工作文件夹；用户指定位置时按其要求保存。

用户明确不落文件时，在对话中完成专项交付。本专项不自行扩成完整行业或企业报告。
