# T｜技术环境分析方法

T 维度分析行业外部技术条件怎样改变产品可行性、性能、成本、交付、采用、替代和竞争门槛，并说明行业内哪些企业类型受到的影响更明显。它不要求展开完整技术史、工程尽调或趋势预测。

## 常见因素

- 核心技术的成熟度、可获得性、可靠性和可维护性；
- 性能、成本、能耗、精度、速度、寿命、安全和规模化变化；
- 算力、网络、能源、设备、数据、开发工具与生产设施等基础条件；
- 标准、接口、协议、互操作性、兼容性和迁移成本；
- 人才、供应商、开源生态、知识产权和关键资源供给；
- 技术替代、路线竞争、模块化、平台化和锁定效应；
- 从论文、原型、产品到部署、使用、续用和经营兑现的采用情况。

## 分析要点

1. 明确分析单位：技术、技术路线、关键组件、基础设施或行业通用能力，不把产品宣传词当成技术定义。
2. 每个核心因素登记：`技术/路线｜当前状态｜性能与成本｜适用场景｜部署条件｜标准/接口｜供应与人才｜采用证据｜时间｜来源版本`。
3. 分开判断“能做出来”“能稳定交付”“有人采用”“能够持续经营”。论文、专利、Demo、产品发布、客户部署、活跃使用和收入分别只证明对应阶段。
4. 技术进步须连接到行业变化，例如成本下降、性能提升、部署周期缩短、需求扩展、替代加速、准入门槛变化或供应约束缓解。
5. 比较技术路线时说明评价场景和约束，避免用单一性能指标宣布全局胜出。
6. 核对互补资产：基础设施、数据、人才、标准、供应链、服务与客户改造是否具备。核心技术可用不等于整体方案可部署。
7. 用采购、部署、利用率、故障、续用、成本、交付、订单、收入、退出或替代等现实信号核对。

## 常见误区

- 论文、专利、发布或融资直接等于商业化成功；
- 实验室性能直接外推真实场景；
- 只看性能，不看成本、可靠性、维护、标准和配套条件；
- 把技术路线预测写成已经发生的事实；
- 把某家企业的产品领先直接当成整个外部技术环境。

## T 维度交付要点

`技术因素与状态｜适用场景｜性能成本与部署条件｜对行业的影响路径｜受影响的企业类型｜方向与时间｜采用证据｜替代与锁定｜不确定性｜证据状态`

如需比较多条路线，可增加路线对比表；如需讨论未来变化，明确时间窗、情景和证伪信号。
