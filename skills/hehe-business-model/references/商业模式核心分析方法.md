## 共用分析方法

### 1. 客户与购买理由

对每种主要模式或目标业务，先说清楚：

`[对象]为[付款者]提供[可验收结果]，通过[获客/签约方式]取得订单，按[计费单位和合同方式]收费，依靠[关键资源与活动]交付，并承担[主要责任]。`

区分参与者：

`付款者｜采购/决策者｜使用者｜影响者｜签约方｜交付方｜渠道/平台｜关键伙伴｜最终责任方`

这些角色可能不是同一主体。分析客户要完成什么任务、解决什么风险，不采用本方案时如何做，改善是否足以让其付费。区分需要、预算、愿意购买与实际复购；用户量、融资或产品发布不能代替付费验证。

### 2. 接单、交付与合作关系

梳理获客、销售、部署、交付、验收和售后的关键活动，说明依赖哪些资源、产能、人才和伙伴。用四流检查交易关系：

| 流 | 当前对象需要回答 |
|---|---|
| 订单流 | 线索从哪来、谁定价、谁签约、订单一次性还是重复、是否受平台或总包控制 |
| 资金流 | 谁先收款、如何分成、预付还是账期、退款/坏账由谁承担、何时变成可支配现金 |
| 数据流 | 交付需要什么数据、谁授权、能否复用、是否形成持续成本或能力积累 |
| 责任流 | 谁承担质量、验收、售后、合规、安全、库存和违约责任 |

重点找四流错位：收入归对象但责任留给伙伴、订单归平台但交付成本由对象承担、利润已确认但现金未回收、数据不可复用却被描述成数据飞轮。

### 3. 收入从哪里来

先区分：

`GMV/交易额｜订单额/Bookings｜合同额｜账单｜确认收入｜ARR/MRR｜客户付款与回款｜合同负债`

沿“客户与使用量 → 定价、折扣与收费 → 履约 → 收入确认”解释收入如何产生。交易、订阅、按量、项目、平台和广告使用不同公式；ARR/MRR是某时点的经常性收入年化/月化指标，不是本期确认收入。进行计算时读取 [商业模式计算方法与算例](商业模式计算方法与算例.md)。

逐项说明收费安排：

`收入单元｜付款者｜计费单位｜价格｜频次/期限｜确认时点｜续费/复购｜退款/折扣｜证据状态`

不得把 GMV、签约额、融资、补贴、累计流水和营业收入混称；一次性项目增长不能自动证明经常性收入。

再整理收入组合，检查有无遗漏及相互支撑：

`收入线｜对应模式单元｜付款者｜计费单位｜主收入/次收入/战略收入｜经常性/一次性/补贴性｜独立盈利/交叉补贴｜已知占比或变化方向｜跨期变化｜证据状态`

- 收入类型采用开放式发现，不限于商品、订阅/授权、项目/服务、内容/会员、广告、平台抽成、数据/API、第三方付款或政府购买/补贴。
- “主收入”“战略收入”和“交叉补贴”必须说明判定依据；没有可靠分部或合同证据时，不估算占比，只登记已知上下限、方向或未知。
- 多边市场分别登记每一侧提供什么、支付什么以及哪一侧被补贴，不能把活跃用户自动写成付费客户。
- 跨期结构变化需区分真实业务迁移、并购、会计重分类和披露口径变化。同一笔收入即使支持多个业务或模式，也只计一次。

### 4. 成本、利润与现金

#### 单位经济与整体成本

选择能够重复的最小经营单元，例如：

`一个订单｜一个客户/账户｜一个订阅席位｜一个项目｜一家门店｜一台设备｜一次内容或交易`

有可用数值时计算，没有时先说明成本驱动与待补参数：

`单位确认收入 − 单位直接投入 − 单位增量交付/服务成本 − 单位渠道与交易成本 − 单位售后/履约责任成本 = 单位贡献`

成本项划分要互不重叠，写清是否已经包含获客成本。单位贡献不等于毛利、经营利润或现金；退款折让、坏账、共享费用分别处理，不重复扣减。公式与例子见 [计算方法](商业模式计算方法与算例.md)。

再说明：

- 获客成本及其回收周期；
- 留存、复购或使用周期是否足以覆盖获客与实施成本；
- 固定成本和必要资本投入需要多少单位贡献才能覆盖；
- 经营者劳动、外协、折旧、退款、坏账和税费是否遗漏；
- 容量扩大后哪些成本下降、保持不变或阶梯式上升。

需要推演时分别建立：

1. **当前表现**：使用当前材料中的数据，缺失项单列；
2. **盈亏平衡情境**：反推达到经营平衡所需的价格、数量、留存或成本；
3. **目标情境**：明确假设未来效率或规模，标为 `[情境]`。

最小单元为负且没有可验证的价格、成本、留存或交叉补贴改善路径时，扩大规模通常只会扩大亏损。不得用尚未验证的远期规模效应覆盖当前单位经济缺口。

#### 从单位成本回到整体成本架构

单位经济不能替代整个模式的成本池。建立成本架构表：

`成本池｜成本驱动因素｜直接/间接｜固定/变动/阶梯｜现金/非现金｜维护/扩张｜可归属/共享｜分摊依据｜证据状态`

结合业务检查研发、产品与技术基础、制造/采购、交付与实施、渠道与获客、客户成功/售后、运营与管理、合规责任、营运资金和必要资本投入。共享成本有合理依据时才分摊；否则报告可归属结果及未包含的成本，可估算时另列含共享成本后的范围，不用零成本填空。

#### 利润质量与现金转换

沿着以下路径核对：

`订单/合同 → 履约 → 收入确认 → 毛利/单位贡献 → 经营利润 → 回款 → 经营现金 → 必要资本开支后的现金`

结合本次问题解释：

- 毛利改善来自价格、结构、采购、交付效率还是成本资本化；
- 利润是否依赖补贴、一次性收益、低计经营者劳动或推迟必要投入；
- 应收、存货、预付、合同负债和应付的变化如何影响现金；
- 维护性与扩张性资本开支是否可区分；不能区分时明确限制；
- 现金改善是否来自真正经营回款，还是延迟付款、融资或处置资产。

单一科目只作为信号，需结合合同、业务增长、季节性和多期同口径变化解释。

需要比较付款分配时，可用“每 100 元客户付款”情境，分别核算付款与收入、收入与利润、利润与现金；完整三段方法见 [计算方法与算例](商业模式计算方法与算例.md)。利润转现金要加回已扣非现金项，再处理营运资金变化与资本开支。情境不冒充行业平均成本率或真实利润。

### 5. 增长与模式组合

先看模式之间怎样组合：哪部分吸引客户、哪部分盈利、哪部分促成留存，客户、数据、渠道、伙伴或产能能否共享。说明协同通过什么机制降低下一单成本或提高价值，以及新增组织成本、资源争夺、交叉补贴与业务蚕食；两条业务同时存在不等于协同。

再解释报告期增长来自：

`数量/客户数｜使用频次｜价格｜产品/客户结构｜续费与留存｜扩容/交叉销售｜份额｜新区域/新产品｜并购｜汇率/会计口径｜一次性事件`

每项增长登记：

`贡献方向｜证据或计算｜是否可重复｜所需新增资源｜对毛利/现金/责任的影响｜失效信号`

增长必须穿过经营闭环：订单增加后，交付人力、推理/云成本、库存、售后、账期、资本开支或合规责任是否同步增加。收入增长但单位贡献、回款或资本效率恶化时，不得称为“规模效应”。

#### 模式演变与扩张边界

增长分解后，再回答模式本身是否正在改变：

`原模式｜触发因素｜付款/交付/成本/责任发生的变化｜所需新增能力｜当前证据｜经营影响｜失败条件`

检查当前模式的饱和约束，以及可能的扩张路径：同一客户增加产品、同一产品拓展客群、新地区/渠道、能力或数据复用、上下游延伸、并购整合。每条路径必须同时写新增获客、交付、组织、资本和责任成本，以及对原业务的稀释或蚕食风险。

“第二增长曲线”只有在新付款者或新增预算、可交付产品、收费方式、所需能力和初步经营验证均能说明时才能写为条件成立；只有发布、试点、融资或愿景时标为 `[待核实]` 或 `[情境]`。本 Skill 判断经营机制，不用未经测算的市场总量证明扩张成立。

### 6. 护城河与持续性

分清行业共有的准入条件、某种模式的结构优势、企业已经建立的独有能力。不要把行业里大家都有的条件写成一家企业的独有护城河。

飞轮必须写成可验证闭环：

`输入变化 → 中间机制 → 可观察指标 → 对下一轮收入/成本/留存的影响 → 饱和或反噬条件`

只有在反馈能够重复出现时才称为飞轮。用户多、数据多、研发高、品牌强或渠道广，本身不能证明正反馈。

护城河或关键能力只有能够持续改善至少一项经营结果时，才属于商业模式结论：

`更高可持续价格｜更低单位成本｜更低获客成本｜更高留存/复购｜更快回款｜更低资本占用｜更低交付或合规风险`

做一次“资金充足的新进入者”压力测试：

`要复制的能力｜钱能否直接购买｜必须积累的时间/数据/认证/关系｜可绕行路径｜对收入/利润/现金的影响｜失效信号`

这里只测试经营机制是否可复制，不制定竞争行动方案、不预测击败概率，也不据此判断总体竞争格局。

#### 成立条件与失效信号

结合本题检查哪些条件已有依据，哪些仍待验证：

- **需求成立条件**：客户有预算、愿意付费并能验收；
- **交付成立条件**：关键资源、产能、数据、人才和伙伴可获得；
- **单位经济条件**：单位贡献与获客回收存在可验证路径；
- **现金条件**：回款、库存、预付、资本开支和融资能够匹配增长；
- **持续性条件**：留存、复购、规模效应或价值协同真实存在；
- **外部依赖**：平台、关键客户、供应商、牌照、补贴或技术基础。

失效信号应可观察，例如：价格下降而成本无法同步下降、续费/复购下降、交付成本随收入更快增长、应收与库存持续快于收入、单位贡献长期为负、关键平台提高抽成、核心伙伴退出或责任成本上升。
