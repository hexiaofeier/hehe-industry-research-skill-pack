# 公司画像交付模板

## 一、交付载体

除非用户明确要求不落文件，否则必须生成可编辑 Markdown 主报告。用户明确不落文件时，在对话中按第二节结构完整交付。

Excel 或 CSV 只在第三节所列条件触发时生成；没有大规模结构化底表、持续更新或数据交换需要时，不另做附件。

## 二、Markdown 主报告

### 完整度与展开要求

先确定输出模式：

- **完整专项报告：** 用户要求完整、深度或系统研究，或者本专项被纳入 `hehe-industry-researcher` 的完整研究时使用。必须覆盖本模板列出的适用主体章节。
- **局部专项答复：** 只在用户明确询问一个局部问题或明确要求简版时使用，只展开与该问题直接相关的章节。
- **有限披露报告：** 只在关键资料确实不足时使用；仍需充分分析现有证据能够支持的内容，不能只交缺口清单。

完整报告的核心主体章节不能只有标题、事实清单、新闻罗列或一张没有解释的表。每项主要结论至少完成“结论 → 关键证据或计算 → 机制、比较或变化原因 → 对本题的含义 → 成立条件或翻转点”的闭环；表格之后解释最重要的差异和意义。

**完整模式正文目标体量：** 完整经营画像一般为 7,000—13,000 汉字；公司事实卡一般为 2,000—4,000 汉字；同口径事实包按业务数量和字段规模展开。 这是完整度检查线，不是写作配额；交付前必须实际统计正文字符数并记录结果。统计只包括推进本题结论的分析；来源清单、原文摘录、附录长表、方法或交付说明、验收记录、通用边界和更新流程不计入，也不得跨专项复制或批量套用同一句式后只替换变量。低于下限时先逐项复查并补足被压缩的核心能力；实质分析已经完整且差距不超过下限 10% 时，可记录偏差后交付，不得为贴线补字。差距超过 10% 且不属于局部或有限披露模式时，不得作为完整专项报告交付。超过上限也不代表更好，应删除重复结论、同义改写和只为防止质疑的说明。


按任务选择一种输出包；用户未指定且材料足够时，默认“完整经营画像”：

| 输出包 | 适用情况 | 必须包含 | 明确不包含 |
|---|---|---|---|
| 公司事实卡 | 核对主体、业务和当前经营状态 | 核心摘要、研究范围、身份与披露制度、核心业务、关键客户/供应商/伙伴/对手、各核心业务的经营验证层级、关键数字口径、主要缺口/风险、证据定位 | 固定字数、综合评价、未经证实的沿革 |
| 完整经营画像 | 单公司基本面、经营质量、成长与战略变化分析 | 以下完整结构 | 完整行业或企业综合报告、估值或买卖建议 |
| 同口径公司事实包 | 为跨公司研究提供统一字段的目标公司底表 | 核心摘要、研究范围、主体/业务边界、链上位置、产品与技术底座、客户供应商等关键关系、各核心业务经营验证、份额口径、优势主张、失败信号、限制 | 其他公司画像、公司排名、格局结论、竞争输赢预测 |

所有输出包的首个正文章节都是核心摘要，第二节都是研究范围。完整经营画像至少包括：

1. **核心摘要**：一句话说明公司当前经营状态，再列三至六项关于核心业务、经营证据、增长与财务质量、战略兑现、优势或风险的主要结论。
2. **研究范围**：法定或经营主体、业务与分部、地域、报告期、判断截止日、研究目的及必要的包含与排除。
3. **公司身份、发展与组织底座**：披露制度、创始人和核心成员、关键发展历程、控制、母子公司及组织结构、员工、投融资、上市和主要股东。
4. **业务、产品与关键经营关系**：业务、产品、客户角色、技术能力、产品变化、各核心业务的 E0—E6 经营验证，以及四张独立关系表：客户清单、供应商清单、重要合作伙伴清单、主要竞争对手清单。
5. **经营结果、增长与基础财务质量**：经营事实、增长来源，以及与公司画像相称的利润表、资产负债表、现金流量表和三表联动分析。基础财务画像不等于 `hehe-financial-analysis` 财务分析专项；只有用户或任务卡明确调用该专项且其独立交付已经完成时，本报告才吸收并标明其核心结论。
6. **管理、治理、资本配置与战略兑现**：说明主要动作、执行状态、可观察结果、偏差与纠偏。
7. **优势、风险与综合判断**：分析优势及其可持续性、风险与反例，给出关键判断状态和会改变判断的信号。
8. **其他说明、附录与待补证内容（按需）**：放长关系表、详细数字、来源、限制和待补信息。

每项关键结论先写清判断的主张，再使用“成立、条件成立、不成立、暂不判断”。输出深度由研究问题、材料完整度和使用目的决定，不按固定字数裁切。

## 三、其他交付物

| 触发条件 | 交付物 | 最低内容 |
|---|---|---|
| 分部历史、产品矩阵、客户/供应商/伙伴/对手关系、事件时间轴或经营验证记录较多，需要筛选、更新或跨表核对 | `.xlsx` | 范围与主体、业务/产品、四类关系、E0—E6 经营验证、关键数字、事件时间轴、来源与状态 |
| 只需交换一张已整理的关系、产品或事件长表，且没有公式 | `.csv` | 主体、业务、对象、关系或事件、期间、口径、来源、状态和限制 |
| 基础财务画像需要少量计算 | 不另生成财务工作簿 | 在 Markdown 中保留公式、口径、来源和结果 |
| 需要标准化三表、完整比率、预测或复杂财务桥，且已有确认结果或当前可用 `hehe-financial-analysis` | 引用已确认结果；需要新算时由 `hehe-financial-analysis` 生成财务工作底表 | 公司画像不重复建设深度财务模型 |
| 各项表格可在主报告中清楚呈现 | 不生成附件 | Markdown 保留四类关系表、经营验证和关键事实 |

没有已确认深度财务结果且当前不可用 `hehe-financial-analysis` 时，不建立深度财务模型；继续完成基础财务画像，并标明未完成的深度分析。

附件按任务裁剪，不生成空工作簿，也不把同一张关系表同时拆成 Excel 和 CSV。

## 四、保存与命名

- 保存位置按[专项工作流程](专项工作流程.md)：有路由时使用任务卡指定位置；单独启动时默认保存到当前任务工作文件夹；用户指定位置时按其要求保存。
- 主报告：`YYYYMMDD_研究主题_公司经营画像.md`；事实卡或同口径事实包可将成果名相应改为`公司事实卡`或`同口径公司事实包`。
- 附件：`YYYYMMDD_研究主题_公司经营画像_附件名称.扩展名`，附件名称写具体用途，如`业务分部与产品矩阵`、`关键关系表`、`事件时间轴`。
- 研究主题写清企业及相关业务；版本号按需添加。用户或项目另有命名规范时优先遵守。

## 五、信息缺口

出现以下情况且会改变主体边界、经营验证、增长质量、战略兑现或风险判断时，生成补证任务并更新相应章节：

- 公司、品牌、产品、子公司或证券主体映射冲突；
- 财务期间、分部、币种、会计或收入确认口径不可比；
- 客户、订单、收入、利润或现金的关键说法只有宣传材料；
- 重大事件的时间、状态或影响对象存在未解决矛盾；
- 负面事件、关联交易、重大风险或数据修订缺少原始材料。

补证任务使用：

`待证问题｜所需事实/字段｜对象与主体｜时间/地域/口径｜可接受材料｜建议检索方向｜不补证的影响｜补充后更新哪一部分`

暂时无法补齐时保留为待核缺口，只限制受影响的业务、期间或结论。

## 六、交付条件与交付前检查

满足以下条件即可结束本次分析：

- 主体、分部、产品和数据范围已经确认；
- 与核心业务有关的客户、供应商、伙伴和主要对手已经说明，或明确标出未披露和待补证；
- 核心业务的经营验证层级和证据缺口已经明确；
- 增长、财务质量、战略动作和主要风险已有可追溯判断；
- 新增材料只补充一般沿革或低影响动态，不改变经营画像。

交付前再检查：

- 核心摘要先给公司当前状态和主要判断，研究范围单独成节；
- 法定主体、上市主体、经营主体、品牌、产品和分部没有混称；
- E0—E6 对每项核心业务分别判断，融资、发布、订单、收入、盈利和现金没有越级；
- 客户、供应商、合作伙伴和竞争对手四张表职责分清，匿名关系没有猜名；
- 增长、基础三表质量、治理与战略动作均连接到可观察结果；
- 输出包、附件触发、文件名称和实际内容一致，链接可打开。
