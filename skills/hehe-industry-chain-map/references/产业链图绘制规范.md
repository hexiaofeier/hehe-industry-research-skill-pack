# 产业链图绘制规范

图要让读者看懂角色、上下游和关键关系；保留可编辑图源，并完成一次面向阅读的排版。用图表达分析，不根据好看的布局倒推产业结构。

## 1. 选图与组织内容

| 图 | 什么时候画 | 节点与连线 |
|---|---|---|
| 角色关系总览 | 标准产业链分析默认提供 | 谁提供什么、交给谁；主要角色和少量代表企业 |
| 功能链／多主链 | 产品变化与经营角色不同，或跨越制造、运营等系统 | 功能与产出变化，主链汇合接口 |
| 核心环节企业图 | 某些环节需要展开企业及真实上下游 | 企业归属与已证实关系；完整名单放表格 |
| 技术路线／瓶颈迁移图 | 课题涉及替代、代际变化或未来约束 | 路线、采用条件、受影响节点；技术来源与替代分清 |
| 企业分布卡片 | 企业多、需要一眼看清分布 | 按环节排列企业，可输出 HTML；不能代替关系图 |

**先按实际关系选布局，再做美化。** 以下是可组合的选择，不是固定行业模板：

| 产业链结构 | 布局方式 |
|---|---|
| 连续长链 | 按上下游从左到右或从上到下展开，配套环节置于对应节点旁 |
| 多路供给汇合／面向多类客户 | 汇合式或分支式，保留各路来源、去向和交付物 |
| 双主链／多主链 | 平行分区，连接真实汇合接口；过密时分图 |
| 平台／多方协作网络 | 按参与方分组；只有真实承担枢纽作用的角色才居中 |
| 回收／反馈闭环 | 主链清楚展开，回流线绕外侧并注明回收或反馈内容 |
| 多种结构混合 | 总览＋关键局部图，通过相同节点编号对应 |

图太密时拆成总览和局部图，不固定层数或节点数。角色图可说明通用业务关系；具名企业之间连线需要具体依据，认证不能画成已批量供货。缺证据的边留在待核对表，不为连通画面补线。

## 2. 二次美化：参考 OPC 图的层次，不套它的行业结构

| 元素 | 默认样式与安排 |
|---|---|
| 画布 | 白至浅蓝背景，四周留白；不强加固定宽高比 |
| 普通角色 | 白色圆角卡片、浅蓝细边；标题深蓝加粗，说明用较浅蓝灰 |
| 关键经营角色 | 浅蓝填色、深蓝较粗边框；用位置和大小突出 |
| 终端需求 | 可用深蓝底白字，与投入和中间环节区分 |
| 配套角色 | 放主链侧边，必要时用虚线边框，不挤占主链 |
| 主关系 | 蓝色实线箭头，优先直角折线；线旁写简短交付物或关系 |
| 支持或政策关系 | 用蓝灰／暗红及虚线区分，图例明确本图含义 |
| 字体 | 微软雅黑、思源黑体等无衬线中文字体；标题与说明有明显层级 |
| 文字与连线 | 节点短标题＋少量说明；边标签放在留白处，不压节点、不遮箭头 |

OPC 仅参考配色、卡片、文字层次和连线可读性，节点与位置由本次产业链决定。蓝／红和实／虚线只区分本图的关系类别，不表示证据等级或好坏。

客户付款方向可能与产品交付方向相反。资金、数据或责任路径太多时另画，不把几种方向挤成一根模糊的线。不要用小字硬塞长名称；把解释移到正文、调大画布或拆图。

## 3. 图源与美化版

- 正常文件交付时，Markdown 中展示美化图，同时附 Mermaid 代码；同内容另存 `.mmd`。
- 美化版优先 SVG，便于放大和排版；需要图片引用时再导出 PNG。
- 正常文件交付附离线 HTML，内嵌美化图和 Mermaid 源码；复用网页模板，不依赖在线加载。
- Mermaid 是关系结构的可编辑表达；SVG 可用手工辅助布局。两者的节点、方向和关系标签一致，坐标不要求相同。
- 改了结构后同步更新图源、底表和展示版。若只改 Mermaid，原有 SVG 不会自动更新；重新生成并核对后再交付。
- 可用当前环境的绘图能力；没有专门工具时，自带 Python 脚本即可生成 SVG、Mermaid 和离线 HTML，不需要联网服务。

## 4. 使用随包模板

按本次产业链新建布局 JSON，可参照 [OPC 风格示例](../assets/产业链图模板.json) 的字段格式与样式。节点、边、坐标和画布重新安排，不必复制示例；政府、园区、平台等只在本题确有对应角色时加入。

运行 [绘图脚本](../scripts/render_chain.py)：

```text
python -B "<本Skill目录>/scripts/render_chain.py" "<目标文件夹>/图名.json" --output-dir "<目标文件夹>" --basename "图名"
```

输出同名 `.svg`、`.mmd` 和 `.html`。HTML 离线显示美化 SVG，并可展开查看 Mermaid 源码；它不是 Mermaid 渲染器。JSON 放在同一目标文件夹，供以后重生成。已有同名文件时脚本默认不覆盖，确认替换后才加 `--overwrite`。

### 布局字段

| 字段 | 含义 |
|---|---|
| `title / subtitle` | 图标题、范围或必要说明 |
| `width / height` | 画布宽高；预留顶部标题和底部图例 |
| `nodes[].id` | 稳定的节点编号，与分析表对应 |
| `title / lines` | 节点短标题、说明行；不是完整企业资料 |
| `x / y / w / h` | 节点左上角坐标、宽、高 |
| `kind` | 卡片样式：`normal/core/terminal/support/policy` |
| `edges[].source / target` | 连线起点与终点的节点编号 |
| `label / type` | 关系文字与线型：`main/support/policy`；分类含义由图例说明 |
| `points` | 从起点边框到终点边框的一组直角折线坐标 |
| `label_x / label_y` | 关系标签位置；应在留白处 |
| `legend` | 可改写本图各线型的解释 |
| `direction` | 按布局选择 Mermaid 排列方向：`TB/LR/BT/RL`；省略时为 `TB`。SVG 位置另由节点坐标和连线路径决定 |

节点和关系可附来源编号供追溯；不必将证据全文画在图上。脚本帮助检查编号、边界、穿框和文字容纳情况，不代替事实审核，也不保证自动找到最佳布局。

## 5. 出图后检查

1. **结构**：节点、边、方向、关系文字与分析表一致，角色与企业没混层，未凭空补线。
2. **语法**：有 Mermaid 渲染器时实际解析／渲染，不以“提取到代码块”当作语法通过。
3. **可读性**：离线打开 HTML，检查标题、节点文字、标签、箭头、图例；无重叠、裁切或靠横向滚动才能读完整图的问题。
4. **对应与保存**：正常文件交付的图源、美化图、重生成数据齐全，报告中的文件引用可打开；按模板降级时，Markdown 与 `.mmd` 结构一致。

Mermaid 的分组、连线和主题配置可参考 [流程图语法](https://mermaid.js.org/syntax/flowchart.html) 与 [主题设置](https://mermaid.js.org/config/theming.html)。
