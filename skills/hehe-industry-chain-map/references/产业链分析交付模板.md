# 产业链分析交付模板

## 一、交付载体

除非用户明确要求不落文件，产业链分析的正常文件交付必须包含以下文件组；当前环境无法实际渲染时，按下述降级方式交付：

| 交付物 | 默认状态 | 作用 |
|---|---|---|
| Markdown 主报告 | 必须 | 讲清产业结构、核心发现、依据和判断边界 |
| Mermaid 图源 `.mmd` | 必须 | 保存可编辑的节点、方向和关系结构 |
| 美化产业链图 `.svg` | 正常文件交付必须 | 提供可缩放的正式展示图；需要位图引用时再附 `.png` |
| 离线图形预览 `.html` | 正常文件交付必须 | 离线查看美化图和 Mermaid 源码 |

用户明确不落文件时，在对话中交付 Markdown 分析和 Mermaid 代码，不生成独立文件。当前环境无法实际渲染时，交付 Markdown 和 `.mmd`，并在文件清单注明未生成 `.svg` 和 `.html`。

## 二、Markdown 主报告

正文先讲清链条与核心发现，再给表格依据。完整任务按以下顺序展开；按需章节没有实质内容时可省略，保留章节连续编号：

1. **核心摘要**：一句话说明产业链怎样运转，再列三至六项核心结构、关键接口、瓶颈、价值或迁移判断及其关键证据；只读本节即可掌握主要结论。
2. **研究范围**：对象、地域、时间、起点/终点、付款者/使用者、包含与排除。
3. **分析配置卡**：决策用途、粒度、节点展开规则、拓扑及省略理由。
4. **功能节点与拓扑表**：必要功能、节点—边、主链/支链/反馈和替代；存在双主链或多主链时分别呈现并标出接口。
5. **角色上下游关系表**：各角色向谁采购、向谁销售或交付，订单、合同、付款、结算和责任如何连接。
6. **分层企业图谱**：各层典型参与主体，以及核心环节更完整的代表性企业、所在角色、上下游关系证据、经营信号、融资/上市状态、入选理由、投资关注和风险。
7. **四流矩阵**：订单、资金、数据、责任的路径及错位。
8. **稀缺层与瓶颈台账**：机制、信号、强度、替代解释和失效条件。
9. **重点环节经济性与权力**：成本构成、利润获取、瓶颈控制分开；结合规格、准入、客户、资金占用、成本传导和责任承担解释。
10. **替代与瓶颈迁移说明**：路径、代价、时间和新约束；涉及技术代际时说明旧问题、新方案、新代价和采用条件。
11. **结构版本与传播表（按需）**：课题涉及结构变化或韧性时，比较前后快照、四流改道、责任迁移、缓冲点、故障传播和恢复路径；静态全景不设置本节。
12. **核心结构判断**：使用`成立｜条件成立｜暂不判断`表达方向明确的命题，并说明限制、反例、不可外推范围和跟踪信号。
13. **其他说明、附录与待补证内容（按需）**：放长表、来源定位、补证任务、需要更新的分析位置及可复用结构字段；支撑正文的关键证据仍留在对应章节。

企业图谱不是 Logo 墙。每层列出能够确认的典型主体，核心环节还要解释企业为何具有代表性；具名供应商、客户和合作关系应能回到原文。投资视角不适用时可不判断“潜在独角兽”，但仍要说明核心环节的经营信号和主要风险。

## 三、其他交付物

### 产业链图文件组

默认提供角色上下游总览图；功能链和角色链不同、存在多条主链时分别呈现并标出接口。企业很多时主图只选有代表性的主体，完整名单留在分层企业表，可另附企业卡片图。技术路线图按课题补充。绘制与美化使用 [产业链图绘制规范](产业链图绘制规范.md)。

图与分析表共用可追溯编号，按当前图涉及的内容保留：

`节点编号｜节点标签｜角色编号｜企业编号｜边/方向｜交易或交付物｜付款方向｜结构拓扑｜主链/支链/反馈｜建议强调对象｜证据状态｜不可绘制或不可比较项`

具名企业关系还应保留双方主体、产品/服务、关系类型、阶段、时间及来源。编号便于查证，不要求把所有证据和长说明挤进节点。

正常文件交付时，在报告中引用美化图并保留 Mermaid 代码块；同内容另存 `.mmd` 和 `.svg`，并附离线 `.html`。需要在 Markdown 中稳定引用位图时再导出 `.png`。使用自带脚本生成时保留布局 `.json`，便于重生成；多张图可合并到一个 HTML。

### 结构数据表

| 触发条件 | 文件 | 最低内容 |
|---|---|---|
| 节点、边或具名主体多到主报告表格难以核对；需要版本比较或后续程序处理 | `.xlsx` | 分表保存节点、边、角色关系、企业、四流和版本，保留 ID、来源、状态和限制 |
| 只需要交换一张已整理的节点表、边表或四流表，且没有公式 | `.csv` | 与报告和图源共用 ID、字段定义和版本 |
| 结构简单，主报告表格已能完整核对 | 不另生成数据附件 | 主报告仍保留关键节点、关系和证据定位 |

结构附件至少保留节点/边 ID、方向、关系类型、版本、适用范围、证据状态和限制。视觉图不能代替可追溯底表。额外的 PPT 版式或品牌定制只在用户明确要求时制作。

## 四、保存与命名

- 保存位置按[专项工作流程](专项工作流程.md)：有路由时使用任务卡指定位置；单独启动时默认保存到当前任务工作文件夹；用户指定位置时按其要求保存。
- 主报告：`YYYYMMDD_研究主题_产业链结构分析.md`。
- 图文件：`YYYYMMDD_研究主题_产业链结构分析_角色关系图.mmd/.svg/.html`；功能链图、技术路线图等使用相应具体名称，同一张图的图源与展示文件同名。
- 数据附件：`YYYYMMDD_研究主题_产业链结构分析_节点表.xlsx`、`_边表.csv`、`_四流表.xlsx`等。
- 研究主题写清行业或细分对象，企业研究加企业名；版本号按需添加。用户或项目另有命名规范时优先遵守。

## 五、信息缺口

材料不足时，先生成产业链补证任务；任务允许且信息能力可用时，在同次调用中实际执行关键补证，不复制采集器或完整审核流程：

`待证主张｜节点/接口/流｜所需字段与口径｜建议时间范围｜可能渠道｜会改变什么结构判断｜补充后更新哪一部分`

- 补到新资料后，保留任务编号、证据定位、受影响节点和结构版本，并更新对应节点、关系与判断。

## 六、交付条件与交付前检查

满足以下条件即可结束本次分析：

- 链条边界和必要节点已经闭合；
- 核心角色的上下游关系能够从交易或交付物、订单、付款和责任中至少一项得到核对；
- 核心环节已有代表性企业，企业标签和具名关系没有超过公开证据；
- 四流已检查，能确认的路径、错位与仍未知的部分分开；
- 作出瓶颈判断时有机制、信号、替代路径和失效条件；材料只支持局部约束或不足以确认行业瓶颈时，写明范围，不强行得出瓶颈结论；
- 正常文件交付时，图源、美化图和底表的节点、方向、关系标签一致，HTML 已离线打开，文字、图例、遮挡和可读性已检查；降级交付时，Markdown 与 `.mmd` 的结构一致；
- 新增节点或玩家只增加名单，不改变结构判断。

以下缺口出现时生成补证任务；未解决前只暂停受影响的节点、路径或瓶颈判断：

- 核心节点是否存在仍依赖未经审核材料；
- 订单、资金、数据或责任路径存在会改变结论的冲突；
- 供应者数量、认证周期、产能或财务信号口径不可比；
- 关键瓶颈只有行业叙事，没有可观察信号。

交付清单核对 Markdown、`.mmd`、本轮交付状态要求的 `.svg` 和 `.html`，以及实际触发的数据附件；已生成文件齐全，报告中的相对链接可以打开。

## 七、其他注意事项与专项要求

本 Skill 自行完成专项分析和基础图形美化。绘制与渲染执行[产业链图绘制规范](产业链图绘制规范.md)；美化只能调整布局、配色和文字层级，不能改变研究确认的节点、方向和关系。
