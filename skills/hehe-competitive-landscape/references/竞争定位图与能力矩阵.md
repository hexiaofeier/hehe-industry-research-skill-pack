# 竞争定位图与能力矩阵

本规则属于 `hehe-competitive-landscape` 自身能力。二维竞争定位图回答“企业分别站在哪里、采用什么竞争路线”，能力矩阵回答“各家具体能力差在哪里”。两者可以单独使用，也可以在回答不同问题时配套交付；不以 `hehe-chart-planning` 或其他制图 Skill 为前置依赖。

## 一、二维竞争定位图

### 1. 触发条件

同时满足以下条件时制作：

- 通常有四家以上可比较企业、产品或业务单元；
- 存在两个相互独立、能够区分主要竞争方式的维度；
- 两条轴会影响客户选择、成本、交付、渠道、变现或切换，而不是为了排版临时拼出的概念；
- 每个对象的位置都能由产品功能、客户、交付方式、渠道、收入模式、部署方式或其他可核事实支持。

以下情况不制作：两条轴同义或高度相关；对象位置主要来自研究者印象；图形实质上是没有评分依据的综合排名；没有同口径市场份额却用气泡大小暗示份额。

### 2. 选轴与定位

按研究问题选择轴，不固定套用通用模板。可用方向包括但不限于：通用工具到垂直工作流、单点能力到一体化方案、封闭服务到开放部署、制作工具到制作与发行连接。使用时必须：

1. 写清两端的含义和方向，并说明轴与竞争结果的关系；
2. 标明比较对象、地域、观察时点或期间；
3. 将定性位置解释为相对位置，不表达为精确测量值；
4. 默认使用等大标记。只有存在同口径定量指标时才改变面积，并注明指标、期间、单位和面积映射；
5. 企业横跨多种路线时，可拆分具体产品或业务单元，避免用集团名称掩盖差异；
6. 在报告或图表说明中为每个标记保留一句定位依据，并指向来源或证据台账键。

### 3. 图面要求

- 标题采用“维度＋结论”，直接说明图中最重要的竞争判断；
- 坐标轴、端点、企业或产品标签、观察期间、来源和必要图注齐全；
- 图注明确“位置为基于公开事实的相对定位”，不得写成份额、排名或精确得分；
- 默认交付可编辑 SVG 与 PNG；画布比例按内容选择，横向图可优先使用约 16:10；
- 颜色用于区分战略群组或对象类型，数量保持可辨，不使用装饰性背景或无含义渐变。

## 二、能力矩阵与热力图

### 1. 触发条件

多家企业、产品或业务单元可以按同一组客户相关能力比较时，形成 Markdown 能力矩阵。通常四家以上对象、四项以上维度时价值较高；对象或维度较少，但比较是报告核心时也可使用。

当行列较多、读者需要快速识别强弱分布或能力空白时，把同一矩阵制作成热力图，并与可阅读的文字表或图表说明一并交付。热力图不能替代证据和差异解释。

### 2. 行列设计

- 行使用同一层级的企业、产品或业务单元，不把集团、单一产品和项目案例混在一起；
- 列选择影响客户购买和企业交付的共同能力，如核心任务完成、角色或资产一致性、流程编排、协作、开放性、部署、后期、发行连接；
- 每一列先定义观察对象、判断标准和时间范围，再比较全部对象；
- 不能适用于全部对象的特殊功能另列补充说明，不塞进共同能力列。

### 3. 单元格与等级

优先填写可比数字或事实。需要定性分级时，只采用已定义的等级：

- **证据覆盖型：** `明确／部分／未见`；
- **能力成熟度型：** `强／中／基础／未见`，并在表前写出各级可观察条件。

`未见`表示在本次公开资料中未找到明确证据，不等于企业没有该能力，也不等于零分。除非已有量化方法、分母和权重，不给等级任意赋分，不加总成综合排名。公司自述、独立测试、客户案例和研究推断需在证据台账中区分。

官方原文明示不支持、未提供或未上线时，直接写对应事实状态及适用版本、套餐或时间，与`未见`分开；正文表格与热力图使用一致标记，图例解释其含义。

### 4. 热力图要求

- 标题采用“维度＋结论”，正文用一至三句指出最显著的能力分布；
- 图例写清每种颜色对应的等级，`未见`使用中性颜色；
- 行列标签完整可读，不用缩写掩盖产品或能力对象；
- 默认交付可编辑 SVG 与 PNG；详细证据留在报告、矩阵或证据台账中，图内只保留读图所需内容。

## 三、统一数据口径

每张定位图或矩阵至少留存以下字段：

`指标或维度｜对象与分母｜时间｜地域｜单位或等级定义｜来源或证据台账键｜该证据允许支持的结论`

不得把用户数、收入、客户数、创作者数和市场份额混成同一排名；不得把不同版本、不同期间或不同地域的数据直接放在同一等级上；不得把公司自述与独立测评当作同强度证据。

## 四、制作、嵌入与验收

1. 优先使用项目已有配色和字体；没有时使用高对比、可打印的简洁配色和常见中文字体。
2. 用本地代码、浏览器或现有渲染能力生成 SVG，并导出 PNG。SVG 为可编辑图源，PNG 为报告展示图。
3. 在 Markdown 报告中插入 PNG，添加图题、精炼结论及来源；SVG 与 PNG 使用相同文件主名。
4. 实际打开最终 PNG 检查：文字裁切、标签重叠、异常空白、轴向、图例、颜色、标记大小、来源和期间。
5. 逐项核对报告、矩阵、SVG 与 PNG 中的企业、产品、维度、标签、期间和结论；图片存在、像素尺寸或文件哈希不能替代视觉检查。
6. 无法可靠定位或分级时，保留文字比较和证据缺口，不生成会制造确定性的图。
